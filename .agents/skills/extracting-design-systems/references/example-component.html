Button

Buttons let people take an action: save, send, delete, open. One primary button per view tells them what matters most.

Overview

Use a button when activating it changes something: it submits, creates, deletes, opens a dialog or starts a process. Use a link when it only takes the person somewhere. Use a menu when one trigger offers several actions.

  • Primary is the one action the view exists for. Never two per view.
  • Secondary (the default look) is for everything else that is still an action.
  • Ghost sits inside dense surfaces: toolbars, table rows, card headers.
  • Link looks like a link but behaves like a button; use it for low-emphasis actions inside sentences.
  • Danger is for destructive actions and only appears after a confirmation step or inside a confirmation dialog.

Anatomy

  1. Leading icon (optional)1.25em square, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; the accessible name.
  3. ContainerHeight from --control-height-*, --radius-md corners, 1px border, horizontal padding from the spacing scale.

Variants

Variants change emphasis, not meaning. Pick by how much attention the action deserves on this view.

Emphasis from highest to lowest; danger is reserved for destructive confirmations.

<button class="btn btn--primary" type="button">Primary</button>
<button class="btn" type="button">Secondary</button>
<button class="btn btn--ghost" type="button">Ghost</button>
<button class="btn btn--link" type="button">Link</button>
<button class="btn btn--danger" type="button">Danger</button>

With icons and icon-only

Icon-only buttons carry aria-label and a tooltip; the icon itself is aria-hidden.

Sizes

Medium is the default. Small lives in tables, chips and toolbars; large is for hero and auth screens where the button is the whole point.

Heights: --control-height-sm/md/lg; padding: --space-3/4/6; font: --font-size-sm/md/lg.

States

Every variant has the same six states. Pointer and focus states are forced here with data-state so they can be reviewed without a mouse; real pages get them from :hover, :focus-visible, :active, :disabled and aria-busy.

Both themes

  • Loading keeps the button's width, hides the label, shows a spinner, sets aria-busy="true" and ignores further clicks. Use it for the action that was pressed, not for the whole form.
  • Disabled uses the native attribute; it is not focusable and is 50% opaque. Prefer leaving a button enabled and explaining the problem on activation when the reason is not obvious.
  • Pressed (toggle buttons) uses aria-pressed; see button group.

Responsive behaviour

  • Below --layout-breakpoint-md (768px) the primary action in a page header or form becomes full width (.btn--block); secondary actions stack beneath it.
  • In dialog and drawer footers, buttons stay on one row and wrap when the row is narrower than their combined width; the primary stays last (rightmost, or bottom when wrapped).
  • Touch targets: medium and large buttons already exceed 44px tall; small buttons (32px) are only used inside rows where the whole row is also a target, and have 8px between neighbours.
  • Labels never truncate; a label that wraps at 360px is too long. Shorten the verb phrase instead.

Theming

The button reads only semantic tokens, mapped into four component tokens (--btn-bg, --btn-fg, --btn-border, --btn-bg-hover) that each variant overrides. A theme changes the semantic tokens; a product re-skin overrides the component tokens; neither touches the component CSS.

/* Re-skin primary buttons for a partner theme without touching .btn */
[data-theme="partner"] .btn--primary { --btn-bg: var(--color-accent); --btn-fg: var(--color-fg-on-accent); }

In the dark theme the accent lightens to --palette-blue-300 and the label flips to --color-fg-on-accent (near-black) so the pair stays above 7:1; the danger button does the same with the red ramp.

Accessibility

Role and pattern

Native <button type="button"> (or type="submit" inside a form). A link styled as a button is still an <a href>; never a <div> with a click handler. No ARIA role is needed.

Keyboard

KeyAction
Tab / Shift+TabMoves focus to and from the button in DOM order.
Enter, SpaceActivates the button. Space activates on key up, so a mis-press can be cancelled by moving away.
EscNo effect on the button itself; a loading button cannot be cancelled with Esc, so offer a separate Cancel when an action is long.

Focus

The shared ring (2px --color-focus-ring, 2px offset) appears on :focus-visible only, so pointer clicks do not show it. On a primary button the offset gap shows the surface colour, which keeps the ring at least 3:1 against both the button and the page.

Labelling

The visible label is the accessible name. Icon-only buttons set aria-label with the verb ("Edit", "More actions for Piranesi") and show a tooltip on hover and focus. Loading buttons keep their name and add aria-busy="true"; a visually hidden "Saving…" is announced through the form's live region, not the button.

Motion

Background and border transition over --duration-fast (120 ms); active state translates 1px. Both are removed under prefers-reduced-motion because the tokens zero the durations. The loading spinner keeps rotating; it is a status indicator, not decoration.

Touch

Medium (40px) and large (48px) meet the 24px minimum and the 44px comfortable target; small (32px) is only used where the surrounding row is also tappable, with 8px between buttons.

Content

  • Labels are verb phrases in sentence case: "Renew loan", "Send reminder", "Delete copy". Never "OK", "Yes", "Submit", "Click here".
  • Say what happens, with the object when it is not obvious from context: "Return copy" in the return dialog, "Return" in a table row.
  • Destructive labels name the loss: "Delete 3 members", not "Confirm".
  • Keep labels to three words where possible; a label that wraps at 360px is too long.
  • Loading has no label change; progress text lives next to the button or in a live region ("Saving your changes…").
