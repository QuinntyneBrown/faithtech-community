Foundation · Iconography

Iconography

39 plain line icons on a 24-unit grid with a 2px stroke, coloured by the text beside them, each with one meaning across FaithTech Community.

Overview

FaithTech Community uses 39 line icons, drawn inline as SVG so they inherit text colour and need no icon font or sprite request. The style is inherited from Shelfie; the set is exactly the icons the FaithTech mocks use, from the bell in the top bar to the arrow on a partner card’s Move button. Icons stay plain and functional: the people, events and partners on the screen carry the warmth, not the icons.

Style

  • Grid: 24 × 24 viewBox, about 2px of padding inside it.
  • Stroke: 2 units, round caps and joins, no fill (.icon sets fill: none; stroke: currentColor).
  • Colour: currentColor, so an icon is always the colour of the text beside it; alerts and toasts set it from their *-icon tokens.
  • Markup: <svg class="icon" aria-hidden="true" viewBox="0 0 24 24"> with paths only; no width, height or colour attributes.
  • Brand mark: the FaithTech mark is the one icon with a second, faded layer (a circle at 35% opacity behind the cross). It is used only in .topbar__brand, including the slim top bar of the public event page.

Labelling

  • An icon beside visible text is decoration: aria-hidden="true", and the text is the name (“Add contact”, “Export CSV”).
  • An icon-only button has an aria-label with the verb and, where it helps, the object: “Close”, “Dismiss”, “Notifications, 3 unread”.
  • When a visible label is short, the accessible name adds the object: the Move button on a partner card is named “Move Maple Street Church to another stage”.
  • An icon that carries status (the clock on an expired invite, the lock on a forbidden page) always sits next to words (“This invite has expired”).

Usage

  • Lead with the icon in buttons and menu items; the label follows.
  • Use one icon per meaning: the check is “done” (Close sprint), the check in a circle is “success”; the counter-clockwise arrow restores, the clockwise one tries again. Do not swap them.
  • Do not add emoji in place of an icon; the mocks use none.
  • Copy paths from this sheet; do not redraw or import icons from another set.

Accessibility

  • Meaningful icons reach 3:1 against their background (1.4.11); the alert and toast icons have dedicated tokens for this.
  • Icon-only buttons are at least 24px (--target-min) and in the mocks 44px (the bell, Close).
  • In forced-colours mode icons follow currentColor and stay visible.
