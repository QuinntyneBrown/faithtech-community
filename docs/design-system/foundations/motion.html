Foundation · Motion

Motion

Quick, purposeful motion that explains what changed (a dialog arriving, a toast confirming, a partner card changing column), all of it switched off when the device asks for reduced motion.

Overview

Motion in FaithTech Community explains what changed: a dialog rises from where it will sit, a toast slides in to confirm “Invite sent”, skeletons shimmer while the partner pipeline loads. It is quick, never blocks input and switches off when the device asks for less motion. There are no celebrations or page-load effects; the timing tokens are inherited from Shelfie, and the FaithTech mocks use the calm end of them.

  • Use a duration token and an easing token together; never a raw ms value or a named CSS easing.
  • No animation on page load except skeleton shimmer.
  • Animate opacity, translate and scale; avoid animating layout.

Durations

Each dot travels the same distance with --ease-standard; only the duration changes. Under reduced motion they jump.
TokenUse
--duration-instantState changes that must not animate: a partner card landing in its new column, a role chip appearing
--duration-fastHover and colour changes, button press, estimate card selection, menu open
--duration-baseToast enter and leave, backdrop fade
--duration-slowDialog enter (Move Kestrel Labs, Send invite)
--duration-deliberateReserved; no FaithTech mock uses it yet
--duration-loopOne cycle of a looping indicator: skeleton shimmer, the busy-button pulse

Easing

Same 320ms, four curves. Spring overshoots and settles.
  • Standard for things that change within the page: hover lifts on estimate cards, colour changes.
  • Enter (decelerate) for things arriving: dialogs, menus, toasts.
  • Exit (accelerate) for things leaving: a dismissed toast.
  • Spring is inherited but has no FaithTech use; do not add one without a mock.

Loading loops

The busy submit button from dialogs/add-partner/busy and a skeleton row from pages/contacts/loading. The spinner turns once every --duration-loop/2 and the shimmer runs one cycle per --duration-loop.

Choreography

  • Dialogs (Move Kestrel Labs, Invite someone to FaithTech, Delete Ben Carter for good?) fade the backdrop (base) and slide the panel up from the bottom on phones or scale in from 96% from 640px (slow, enter). Closing is instant so focus returns to the trigger at once.
  • Toasts (“Invite sent”, “Contact restored”, “Your RSVP wasn’t saved”) slide up into place (base, enter); the newest enters at the bottom of the region. Leaving, they fade (base, exit). The progress bar shows the time left and pauses on hover and focus.
  • Bell panel opens and closes without animation, like a menu that is already anchored to the bell; only the unread count changes, instantly.
  • Kanban card move: after the Move dialog saves, the card appears in its new column with no travel animation (instant) and keeps focus there; while dragging, the lifted card uses the hover lift (fast, standard). No card flies across the board.
  • Skeletons shimmer in the shape of the content they replace (list rows on Contacts, columns on the partner pipeline, cards on Events) and are swapped for content in one step, never faded row by row.
  • Estimate cards in Planning Poker lift slightly on hover and change colour when picked (fast, standard).
  • Nothing moves on its own after a page has settled except a loading indicator.

Reduced motion

Under prefers-reduced-motion: reduce, tokens.css sets every duration to 0.01ms, so transitions and entrances become instant without any component change. components.css also stops loops after one pass and turns off the skeleton shimmer. The busy-button spinner still shows because it tells the person their invite or RSVP is on its way.

  • No animation flashes more than three times a second (2.3.1).
  • Smooth scrolling is turned off too.
  • Test with DevTools: Rendering → Emulate CSS media feature prefers-reduced-motion.

Usage

  • If a motion does not explain a change, remove it.
  • Never delay input behind an animation; a dialog’s buttons work while it is still easing in.
  • Never animate a partner, contact or person moving between lists; show the result and move focus with it.
  • Use standard and enter for everything; exit only for things that leave on their own.
