Layout

A mobile-first grid of 4, 8 and 12 columns whose gutters and margins grow at 768px and 1024px, a 1280px container and six page templates.

Overview

FaithTech Community is mobile first (the grid is inherited from Shelfie unchanged). Base styles target a 360px phone; two breakpoints (768px and 1024px) add columns, wider gutters and wider margins by changing three tokens, so components rarely need their own media queries. Content is centred in a 1280px container.

  • Lay pages out on .container + .grid; the grid reads --layout-columns, --layout-gutter and --layout-margin.
  • Use min-width queries in rem only. Resolved drift: components.css used to hide .nav-link--secondary with a (min-width: 48rem) and (max-width: 63.99rem) range; it is now hidden by default and shown from (min-width: 64rem).
  • No page scrolls sideways at 320px.

  • .grid is repeat(var(--layout-columns), minmax(0, 1fr)) with gap: var(--layout-gutter).
  • .span-4, .span-5, .span-7, .span-8 are full width until 1024px, then take that many of 12 columns. The FaithTech mocks use .split (2fr + 1fr) instead for home and event detail; use 8 + 4 for any new main column with an aside.
  • .grid--auto fills cards at a minimum of 18rem each; .photo-strip fills profile photos at 7rem each.

Container and measure

  • .container is full width, capped at --layout-container-max (1280px), centred, with --layout-margin on both sides.
  • Prose stops at --layout-measure (65ch); every <p> has it as a max-width.
  • The auth card is 26rem wide and centred in the viewport (.auth-layout, .auth-card); a dialog panel is 32rem; page forms cap with .form-width--sm (40rem: new contact), --md (44rem: settings, compose announcement, its success card and the danger zone) or --lg (48rem: edit profile, the event form, workspace settings); <ft-stack width="sm|md|lg"> in Angular.

Tab bar on phones (64px, --layout-tabbar-height): Home, Events, Search, Contacts, Partners. From 768px it hides and the top-bar nav takes over.
  • The top bar is 56px (--layout-topbar-height), sticky, and the page sets scroll-padding-top to its height plus 16px so focused and linked content is never hidden under it.
  • The tab bar is fixed to the bottom on phones, adds env(safe-area-inset-bottom), and the page wrapper .has-tabbar pads the bottom so nothing sits under it.
  • --layout-sidebar-width (256px) is used by this documentation site's navigation only; the FaithTech app has no sidebar. Workspace sections (Board, Backlog, Settings) use .tabs under the page header instead.

Usage

  • Put spans on grid children with the .span-* classes; never write style="grid-column: span 8" plus a max-width override .
  • A page has one .container; full-bleed elements (top bar, banners) sit outside it.
  • Use 100dvh, not 100vh, for full-height layouts so mobile browser bars do not clip content.
  • Never hide content at a breakpoint that is not reachable another way. Resolved drift: the hidden sections used to be reachable only from Home. Under 768px the tab bar's More, and from 768 to 1023px a More button at the end of the top-bar nav, open the Main menu drawer of every section.

Accessibility

  • Reflow (1.4.10): every page works at 320px CSS width with no sideways scroll; only data tables scroll, inside .table-wrap.
  • Focus not obscured (2.4.11): the sticky top bar, fixed tab bar and toasts never cover the focused element.
  • Order (2.4.3): visual order equals DOM order at every width; the home “Activity” aside and the event RSVP card come after the main column in the source.
  • Landmarks: one header, nav (labelled "Primary" or "Primary, phone"), main per page.
