Color

Calm surfaces, one violet accent for the next thing to do, seven pastel avatar tints and four status hues, in a light and a dark theme that both pass WCAG 2.2 AA.

Overview

FaithTech Community's colour is calm surfaces, one violet accent for the next thing to do (RSVP, Send invite, Publish), seven pastel avatar tints and four status hues. The violet brand is inherited from Shelfie until FaithTech brand colours are supplied; swapping it is a semantic-token change only (see Adding a brand theme). Colour lives in two tiers: primitives (--palette-*) are raw ramps that nothing reads directly; semantic tokens (--color-*) name a job ("text on a card", "selected chip edge") and are what components use. A theme swaps the semantic tokens and leaves the primitives alone.

  • Use the semantic token that names the job, never a palette step.
  • Pair every foreground with the background it was checked against in contrast.
  • Status is never colour alone: each alert, toast and field error has an icon and words.

Primitive ramps

Violet: the brand

Primary buttons, links, selected states, the focus ring and the current nav link. 600 is the light-theme accent; 300 takes over in dark.

Gray: neutrals

Text, surfaces and borders. 150, 350, 450, 475, 750 and 925 were added so the dark theme no longer uses raw values (drift D1).

Blue: information

Only for informational messages (the "Read-only for Staff" banner, "Tomás signed up" on a contact). Never for actions.

Green: success

Saved, sent and confirmed: "Invite sent", "You’re going", the Confirmed partner column and the active role badge.

Amber: warning

Warnings: offline, sign-in paused after too many attempts, "Saved, but email is paused" and the pending invite badge.

Red: danger

Errors, invalid fields, the unread count badge, Cancelled event badges and the Archive contact and Suspend account buttons.

Avatar pastels

The seven pastels behind initials avatars (avatar--sky, avatar--sage and so on). They never change with the theme and always carry dark text. The token names keep the inherited cover prefix.

Pastel tints and deeps

Each pastel has a pale tint (the pastel at 50% over white) and a near-black deep that keeps the hue. They are the light and dark bases of the accent surface tints (--color-tint-*); nothing reads them directly.

Base

--palette-white and --palette-black are the two ends. Only the light surfaces, the on-accent label and the dark-theme backdrop read them, through semantic tokens.

The toast sits on the inverse surface, which flips between themes, so its icons have their own *-icon-on-inverse tokens. Before extraction the dark-theme toast icons measured 1.4 to 1.8:1 (drift D2); they now pass 3:1 in both themes.

Avatar and accent tints

Every member without a photo gets an initials avatar in one of seven pastels (Grace Okonkwo is sky, Samuel Mensah mint, Ruth Alvarez rose). The pastels stay the same in both themes so a person looks like themselves everywhere, and the initials always use --color-fg-on-cover. An avatar is decorative next to the name (aria-hidden="true"); when it stands alone it is role="img" with the person's name.

Surface tints

A card or hero can take a pale wash of a pastel (--color-tint-*) by setting --card-bg; the inherited automatic selector (.card:has(> .cover--sky)) is not used by any FaithTech mock. Light themes use the pale tint; dark themes use the deep base so the card still reads as raised. Muted text, accent text and the primary button pass on every tint in both themes.

Contrast pairs

Every pair in tokens/contrast-pairs.json, measured live in both themes. 4.5:1 is the minimum for text (WCAG 1.4.3); 3:1 for control edges, meaningful icons and the focus ring (1.4.11, 2.4.11). The one pair with a 1:1 minimum is a decorative alert border: the tinted background, the icon and the words carry the meaning. scripts/check_contrast.py checks the same list from the command line.

Usage

Rules

  • One accent per view. The violet fill marks the next step: "RSVP", "Send invite", "Publish announcement". Everything else is secondary or ghost.
  • Text tokens follow the surface. Muted text on a subtle chip is checked; muted text on the accent fill is not. If a pair is not in the list, add it to contrast-pairs.json and run the checker before shipping.
  • Danger is for loss. The red fill appears only on "Archive contact", "Suspend account" and "Cancel event" inside their confirmation dialogs, and on the unread count badge.
  • Blue is information, not action. Links and buttons are violet.
  • Avatar tints are identity, not status. Never use an avatar pastel to mean "done" or "waiting"; use the status tokens with an icon and words.
  • No raw values. No hex values, colour functions or colour names in components or pages; check_design_system.py fails the build on them.

Adding a brand theme

A theme is a block of semantic overrides. Pick existing palette steps (or add a new ramp under Primitives), override only --color-* tokens, set color-scheme, then run the contrast checker for every pair. Components need no changes.

[data-theme="sunrise"] {
  --color-accent: var(--palette-amber-700);
  --color-accent-hover: var(--palette-amber-900);
  --color-accent-active: var(--palette-amber-950);
  --color-accent-subtle: var(--palette-amber-50);
  --color-accent-subtle-hover: var(--palette-amber-100);
  --color-fg-accent: var(--palette-amber-700);
  --color-focus-ring: var(--palette-amber-700);
  color-scheme: light;
}

See Theming for where the block goes and how to test it.

Accessibility

  • Text reaches 4.5:1 on every surface it sits on, in both themes, including the pastel avatars and tints.
  • Controls and icons that carry meaning reach 3:1: input edges (--color-border-strong), the focus ring, progress fills against their track, the pressed chip edge and the toast status icons.
  • Decorative edges (--color-border-default) are exempt and say so; the control they belong to is identified another way.
  • Use of colour (1.4.1): links are underlined, status always has an icon and words, a pressed chip has aria-pressed, the current nav link has aria-current, and role badges carry words.
  • Preferences: under prefers-contrast: more decorative borders become strong and muted text becomes default; under forced-colors: active the focus ring becomes Highlight and borders CanvasText.
