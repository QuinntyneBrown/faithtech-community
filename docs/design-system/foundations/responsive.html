Responsive

Designed at 360px first, then given columns, navigation and room at 640, 768 and 1024px, with every control sized for a thumb.

Overview

Leads like Grace Okonkwo move partners and check RSVPs on a phone at events and plan sprints on a laptop; members such as Samuel Mensah open a Builders Night invite or a public event link on whatever is in their hand. Every screen is designed at 360px first and gains space, columns and navigation as the window grows. Breakpoints and grid tokens are on Layout.

Mobile-first rules

  • Base CSS is the phone layout. Add to it with @media (min-width: 40rem | 48rem | 64rem); never undo a desktop layout with max-width. Drift: the secondary nav-link rule in components.css still uses a max-width: 63.99rem range.
  • Prefer intrinsic layouts that need no query: .cluster wraps, .grid--auto fills, flex-wrap on button rows.
  • Spacing and type do not scale with the viewport; only --layout-gutter, --layout-margin and --layout-columns change.
  • Use 100dvh for full-height screens and env(safe-area-inset-bottom) for anything fixed to the bottom.

Touch and pointer

  • Every control is at least 44px tall (--control-height-md); small buttons (36px) only appear in rows that are spaced 8px or more apart.
  • Nothing depends on hover. Hover lifts and row highlights are extras; the same information is visible without them.
  • No gesture is the only way: Kanban cards can be dragged on a pointer device (partners/dragging) but every card also has a “Move” menu (2.5.7). There is no swipe-to-dismiss or long press; every toast and banner has a close button.
  • Planning Poker cards (1 to 21 and ?) are full-size buttons in a wrapping row so a vote can be cast with a thumb.
  • (pointer: coarse) is not used to grow targets; they are already large. Small ghost buttons on Kanban cards (36px) sit in rows spaced 8px apart.

Accessibility

  • Reflow (1.4.10) at 320px; orientation (1.3.4) is never locked.
  • Target size (2.5.8): 24px minimum everywhere, 44px for primary actions such as RSVP and “New event”.
  • Focus not obscured (2.4.11): the fixed tab bar and sticky top bar are accounted for with padding and scroll-padding-top.
  • Consistent navigation (3.2.3): destinations keep the same order at every width; the tab bar is a subset of the top-bar nav plus Search.
