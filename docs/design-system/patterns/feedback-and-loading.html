Pattern · Feedback

Feedback and loading

Every wait has a shape and every action has an answer. Loading shows a skeleton of what is coming. Saving shows on the button that was pressed. The result appears where the person is looking, and it always says whether anything was lost.

Overview

  • Skeleton: grey blocks shaped like the rows, cards or profile that are loading. Every screen with data has a loading state.
  • Busy button: the pressed button swaps its label for a spinner (the label stays in the markup as its accessible name) and sets aria-busy and aria-disabled. Used in every form and dialog.
  • Upload progress: a photo item with aria-busy (on the item that holds the status line, not the thumbnail), a progress bar when the percentage is known, and a status line ("Uploading… 60%"). If the upload fails, the tile shows the error.
  • Inline alert: the result in context. "Profile saved", "Settings saved", "That didn’t work".
  • Success card (.card--success): replaces a form after a send that can't be undone, such as "Sent to 41 Product Engineers".

Toasts, banners and the bell are on notifications. Screens that are empty or failed are on empty and error states.

If loading takes less than about 300ms, don't show a skeleton at all. That avoids a flash.

Responsive behaviour

  • Skeletons use the same layout as the content they stand in for, so nothing jumps when the content arrives (no layout shift).
  • Busy labels can be longer than idle labels. Buttons grow to fit and never cut off "Creating account…".
  • Alerts span the form card at every width. On phones, their actions drop below the text.

Accessibility

  • A loading region has aria-busy="true" and a label ("Loading contacts"). The skeleton blocks are aria-hidden. When the data arrives, aria-busy is removed and focus stays where it was.
  • The pressed busy button uses aria-busy plus aria-disabled, not disabled, so it keeps focus and the screen reader reads the new label. The other buttons in a busy dialog (Cancel, Close) use native disabled.
  • Success results use role="status". Failures use role="alert", and in a dialog focus moves to the alert. Upload progress is a role="status" line with the percentage written out.
  • The skeleton shimmer stops with reduced motion (prefers-reduced-motion). The text still shows the state.
  • A result never relies on colour alone. It has a title and an icon.

Content

  • Busy labels on page forms use the "-ing" form: Saving…, Sending…, Publishing…, Creating account…, Signing in…. Dialog buttons keep their label and add an ellipsis: Delete permanently…, Suspend…, Move to Confirmed…. Use a real ellipsis character.
  • Success says what is now true for others: "Everyone signed in can now see your changes." or "Your notification preferences take effect straight away."
  • Failure says that nothing was changed or lost: "Nothing was changed — try again." or "Anything you were typing is still here."
  • Limits give the actual numbers: "team.jpg is 9.4 MB. Photos can be up to 5 MB — try a smaller one."

  • The skeleton list rows use an inline style="flex:1;" on .list__body.
  • The success card heading uses an inline style="font: var(--text-h4);".
