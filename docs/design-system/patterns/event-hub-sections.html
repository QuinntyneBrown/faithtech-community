Event hub sections

An event hub is made of sections, each with a fixed shape and a fixed layout. Every section has one display that renders it on the hub, in the section preview and on a wizard’s review step. The displays are composition in the events library, built only from components-library primitives; there is no page builder and no styling panel.

Overview

The hub home lists the sections as checklist rows. Fill in or Edit opens that section’s wizard (a dialog, with a stepper for the two-step Agenda and People); the row’s “More for {Section}” menu offers Preview and Hide section; Reorder on the Sections card opens “Reorder sections”, a reorderable list.

The seven display components (hub-hero, hub-agenda, hub-venue, hub-people, hub-links, hub-giving, hub-upcoming) live in frontend/projects/events. They add no new library component. The only new rules are the agenda’s time column and its out-of-hours warning, .hub-section__time and .hub-section__warning in assets/components.css.

When to use

  • For every section of an event hub: on the hub itself, in the "{Section} preview" dialog and on the review step of the Agenda and People wizards.
  • Not for the hub home: that is the checklist of checklist rows, which shows each section's state, not its content.
  • A new section kind (Phase 2: Parking, Tracks, Judging and others) gets a display of its own, documented here, composed the same way.

Structure

  1. Section: <section class="hub-section"> labelled by its heading; a column with --space-3 between parts.
  2. Heading: h3.section-title on the hub (the hub page owns the h1 and h2s). In the preview dialog and a review step the dialog title names the section, so the display drops its heading.
  3. Body: library primitives only: list, avatar, badge, description list, event card, card, button and link.
  4. Live values: anything the system knows (event, organisation, members, upcoming events) is read when the hub is read, never copied into the section (design rule 4).

Hub page

The hub page (/public/events/:id/hub, inside the public shell) stacks the displays of every visible, Ready section in the hub’s order, 48rem wide (ft-stack width="lg") with --space-8 between sections. Upcoming events is left out when there are no upcoming events. Nothing is refused at publish: an empty section is simply left out. The page adds no new component or token.

  1. Page heading: a visually hidden h1 “{event} hub”; the Hero already shows the event’s name, so the page does not repeat it. Each display keeps its h3.
  2. Preview banner: shown only to people who manage hubs. Visitors and members (slice 44) see the same page without it; the page title is the event’s title and the meta description its subtitle, or “{day} · {time} · {venue or Online}”. An alert info with the heading “Preview”, the draft or the published sentence, and a small Back to hub home button link in its actions.
  3. Sections: the seven displays above, in order, each with its heading.

Not available

This hub isn’t available

It may not be published yet, or the link may be wrong.

An anonymous visitor reads “It may not be published yet, or it may be for members only. Members can sign in to see it.” with a primary Sign in that returns to the hub; members keep this text and no button. 403 and 404 read the same, so the page never says whether a hub exists: an empty state at heading level 1 on the page. Loading is skeleton cards in a status “Loading hub”; a failed read is the error empty state “We couldn’t load the hub” with Try again.

Preview, publish and share from the hub home

  • Every hub wizard puts a ghost, small Preview link button (read-only-view icon) at the top of its body. It opens the hub page in a new tab and says “the hub (new tab)” to screen readers. It shows what has been saved; the wizards save as you go.
  • The Your hub card carries Preview (secondary link, same tab) and Publish (primary; busy “Publishing…”) or Unpublish (secondary), which asks first in a danger dialog “Unpublish the hub?”. A published hub adds a “Published” date to the card’s description list.
  • Results are toasts: “Hub published”, “Hub unpublished”, “Link copied”, and danger “We couldn’t publish the hub” with Try again.

Live agenda

On the hub page (for visitors, members and the manager’s preview alike) the Agenda shows where the event is now. The section preview dialog and the wizards’ review steps show the plain rows. Slice 44, L2-168.

Row stateWhenLooks likeSays to a screen reader
FinishedThe row has endedTitle in --color-fg-muted (.list__item--finished); no badge“Finished” (visually hidden, in the status line)
Happening nowNow is inside the row.list__item--current: --color-bg-subtle background, a --space-1 bar in --color-accent on the start edge, success badge “Happening now”aria-current="time" and the badge text
Up nextThe row after the current one; before the event starts, the first rowNeutral badge “Up next”The badge text
PlainEvery later rowThe slice-42 rowThe row
  • A row runs from its start to the next row’s start; the last row runs to the event’s end. Times are compared as instants, so the highlight is right wherever the visitor is; they are shown in the visitor’s time zone like every event time.
  • After the last row ends every row is Finished, nothing is highlighted, and a quiet line under the heading says “This event has finished.” Before the first row starts only the first row is marked, “Up next”.
  • The page re-checks every 30 seconds. A polite live region (role="status", visually hidden, inside the section) speaks only when the current row changes: “Happening now: Code freeze”, or “This event has finished.” at the end. Nothing is announced on first load or on a tick that changes nothing.
  • Nothing animates: the highlight moves without a transition, so there is nothing to reduce under prefers-reduced-motion. In forced colours the bar becomes a Highlight border and the badge keeps its text.

  const timer = setInterval(() => this.now.set(this.clock.now()), 30_000);
  inject(DestroyRef).onDestroy(() => clearInterval(timer));

// Each row runs from its start instant to the next row's start; the last row to the event's end.
// Instants are compared, so the highlight is right in any time zone; times are shown in the visitor's zone.
readonly timeline = computed(() => agendaTimeline(this.rows(), this.eventEndsAt(), this.now()));

  computation: (key, previous) => previous === undefined ? '' : this.timeline().spoken });

Open the event hub

When an event’s hub is published, the public event page and the member event page link to it with an “Event hub” card: the one line “The agenda, venue, people and links for the day, in one place.” and a secondary button link Open the event hub with the hub icon. On the public event page it sits under About, so on a phone it comes before the RSVP card; on the member event page it follows About in the main column. A draft hub, or no hub, shows nothing. Leads keep Open event hub in the header, which goes to the hub home, not the hub page. Slice 44, L2-167.

Responsive behaviour

  • Every display is one column at every width and fills the hub’s content column; nothing scrolls sideways at 360px.
  • The agenda time column narrows from 4.5rem to 3.75rem under 40rem; titles and details wrap beside it.
  • Hero: the body wraps under the eyebrow; the RSVP button stays at least 44px tall.
  • People and Upcoming events stay lists, not grids, so names and meta lines never truncate.
  • In a dialog (preview, review step) the display uses the wide dialog on tablet and desktop and the bottom sheet on a phone.

Accessibility

  • Each display is a <section> named by its h3; People’s groups are lists named by their group headings.
  • On the hub page the current agenda row has aria-current="time" and the visible badge “Happening now”; finished rows say “Finished” to screen readers; colour is never the only signal. A polite live region announces only a change of current row (Live agenda).
  • Links say where they go: “Submit your project”, “Give feedback”, “Open in maps”, “RSVP”, “Give”. Links that open a new tab say so to screen readers.
  • Avatars are decorative (aria-hidden); the name next to them is the text.
  • In the wizards, every move in a reorderable list is announced politely (“Moved Doors open down to position 2 of 5.”, “Moved Agenda down to position 3 of 7.”), and every field error is tied to its field with aria-describedby.
  • Light and dark come from the tokens; there are no fixed colours.
