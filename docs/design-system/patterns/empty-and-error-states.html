Pattern · Feedback

Empty and error states

An empty or failed screen still does a job. It says why there is nothing here, and offers one useful next step: add the first contact, try another search, try again, or ask the right person.

Overview

All of these use the empty state block (.empty): an icon, a title, one or two sentences and the actions. Errors add .empty--error and role="alert". Screens that replace the whole page (forbidden, not found, server error, offline) use the same block as the page's <h1>. See error page.

The mocks have seven kinds: first use (empty), no results, load failed (error), not allowed (forbidden), not found, server error and offline.

Forbidden is a permission rule

Respond with forbidden, not an empty list, when the person's role can't see the data. Examples: Staff opening contacts ("Contacts are private to each lead"), a Volunteer opening a workspace they are not in ("You’re not a member of this workspace"), or a lead opening admin ("This area is for System Admins"). The server sends the refusal, so a page never shows an empty list that is only pretending to be empty.

Responsive behaviour

  • The block is centred, and its text is limited to about 36 characters per line for the title and 60 for the text.
  • Inside a region, the block replaces only that region. The page header and its actions stay, so "Add contact" is still at the top.
  • Full-page states have --space-12 of padding above, and keep the top bar and tab bar, so the person can still go somewhere else.
  • Under 640px, buttons in .empty__actions fill the width.

Accessibility

  • The title is a real heading. It is an <h2> inside a page and the <h1> on full-page states. The page <title> changes too (for example, "Page not found").
  • Load errors have role="alert", so they are announced when they replace a skeleton. A no-results block that appears after a search is announced with a polite live region ("No one matches “xavier”").
  • Icons are aria-hidden. The title carries the meaning.
  • Pages that are not found or not allowed return the right HTTP status (404 or 403), not 200.
  • The forbidden copy never confirms that a private item exists. "You don’t have access to this" is used whether or not the contact exists.

Content

  • Empty: say what this place is for, then invite the first step: "Track churches, companies and foundations from first conversation to confirmed. Every lead sees the same board."
  • No results: repeat the query in quotes and say what search covers: "Search looks at names and your notes. Archived contacts aren’t included."
  • Error: "We couldn’t load …" followed by the same reassurance every time: "Check your connection and try again. If it keeps happening, we’ve already been told about it."
  • Forbidden: name the person who can help: "Ask Grace Okonkwo, your City Lead", or "contact Priya Shah".
  • Server error: take the blame: "It’s not you." Give a reference code that support can look up.

Do and don't

Sources

  • Empty: contacts, partners, workspaces, events, announcements, invites, archived-contacts, profile, notifications, audit-log
  • No results: contacts, people, search, events, team, admin-users, audit-log
  • Error: partners, audit-log, contacts, events
  • Forbidden: forbidden, contacts, people, admin-users, backlog, workspace-settings
  • Newer screens: reports/empty (names the city and period), reports/error, reports/forbidden ("Reports are for Staff and System Admin": says who can see it and where City Leads find their numbers), event-check-in/forbidden ("Check-in is for event leads", names the lead roles and sends the member back to the event, where their RSVP is safe), event-check-in/cancelled (not empty: the list stays for reference under a record-state alert), event-check-in/empty, event-check-in/no-results (the action uses the search term: "Add “Mira” as a walk-in"), event-check-in/error ("Check-ins you already saved are safe."), partner/activity-empty
  • Full page: not-found, server-error, offline; expired: accept-invite/error, reset-password/error

Drift noticed in the mocks:

  • Full-page states put the block in a .error-page wrapper, which adds padding-top: var(--space-12). Never set the offset inline.
  • "Try again" is an <a> that links to the default state. In the app it should be a button that runs the request again.
  • Load-error copy is the same on 26 screens. That is deliberate, but it is not stored anywhere as one shared string.
  • The bell's empty state uses <p class="empty__title"> while the pages use headings.
