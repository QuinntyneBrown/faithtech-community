Pattern · Access

Private preview wall

While the product is in private preview, every visitor to app and www first sees one plain page with a passphrase field and an Unlock button. It is drawn from the same tokens and component classes as everything else, but carries no logo, no product name, no description and no brand colour.

Overview

The wall is composed of the card in the auth layout, one form field with its inline error, the alert for lock-out and server errors, and a full-width large primary button. Its <html> carries data-accent="neutral", which loads tokens/neutral-accent.css after tokens.css: the accent, link and focus-ring roles become greys in both themes, and every other role is unchanged.

It is not an Angular screen. The server renders it before either application bundle is allowed to load, so it cannot use frontend/projects/components (whose bundle and ft- selectors would describe the product). The server's template (backend/src/FaithTech.Community.Api/Middleware/PrivatePreview/wall.html) inlines the few rules of these classes that it needs, by role, under a per-response CSP nonce (ADR 0026). When this page changes, change that template in the same commit.

When to use

  • Only for the private-preview wall (L2-100 to L2-103), on both hosts, for any path, while PrivatePreview:Enabled is on and the visitor holds no valid unlock.
  • Never inside the apps. Sign-in, forbidden and not-found pages keep the brand; see empty and error states.
  • Use the neutral accent scope for any future page that must not identify the product. Do not use it to restyle a branded screen.

Responsive behaviour

  • The auth layout centres the card at every width; the card is at most 26rem wide and fills the width, less the layout margin, on a phone.
  • No navigation, footer or tab bar at any width: there is nothing to navigate to.
  • Controls stay 44px or taller; the button fills the card.

Accessibility

  • One <h1>, a <main> landmark, a skip link and lang="en". The passphrase field has a visible <label>.
  • An error is tied to the field with aria-describedby and aria-invalid, and the field gets focus on load. Lock-out and server errors use role="alert".
  • The neutral focus ring (grey 900 in light, grey 150 in dark) keeps at least 3:1 against the card and the canvas.
  • The form works without JavaScript; the only script adds the busy state.
  • Light and dark follow prefers-color-scheme; there is no stored theme to read before unlocking.

Content

  • Title, page title and heading: “Private preview”. Nothing else names the site.
  • Lead: “This site is not open yet. Enter the passphrase to continue.”
  • Refusal: “That passphrase didn’t work. Check it and try again.” Never say whether the field was empty, the form expired or the passphrase was close.
  • Lock-out: “Too many attempts” · “Wait a few minutes, then try again.” No countdown.
  • Server error: “Something went wrong” · “Try again in a moment.” No reference code: a code would name the logging system.
