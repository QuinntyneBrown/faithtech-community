Person picker

A combobox for choosing members by name. Suggestions show the avatar, name, role and city; chosen people become removable chips. Multiple for sharing, single for a new owner.

WCAG 2.2 AAStatus: newft-person-picker

Overview

Use the person picker when the list of possible people is too long for a checkbox group: Share with → People in Add and Edit a resource (multiple), and New owner in Transfer ownership (single). The feature supplies the matches; the component never calls the API. For a short known set, such as workspace members, keep the checkbox group.

  • Multiple: chips for everyone chosen, the input stays for more.
  • Single: choosing a person replaces the input with one chip; removing it brings the input back.

Anatomy

  1. Label"People" or "New owner".
  2. ChipsChosen people, "Remove {name}".
  3. InputPlaceholder "Search members by name".
  4. AvatarAvatar sm with the featured photo or initials, decorative.
  5. Name and detail.combobox__title and .combobox__detail "{role} · {city}".

Theming

Same tokens as the tag input, plus the avatar colours.

Accessibility

Role and pattern

APG combobox with list autocomplete, as the tag input. The listbox is named "Matching members" or "Members who can own resources"; each option's name is the person's name and its description the role and city. Choosing or removing someone is announced politely ("Hannah Kim added").

Code

<ft-form-field label="People">
  <ft-person-picker
    [multiple]="true"
    [people]="chosen()"
    [suggestions]="matches()"
    suggestionsLabel="Matching members"
    placeholder="Search members by name"
    [loading]="searching()"
    (query)="searchMembers($event)"
    (peopleChange)="chosen.set($event)" />
</ft-form-field>
Class / attribute / inputEffect
[multiple]Many people (chips) or one.
[suggestions]{ id, name, initials, photoUrl, detail }[] from the feature.
[loading]Shows "Finding members…".
(query)Emits the typed text.
(peopleChange)Emits the chosen people.
