Estimate card picker

The deck of planning-poker cards a workspace member votes with: 1, 2, 3, 5, 8, 13, 21 points, or ? for Unsure. Each card is a toggle button; one can be pressed at a time. Each card is a .estimate-choice.

Overview

Use the estimate card picker for a single choice from a short, fixed scale where the choice should feel like laying down a card. Today it is the "Your vote" card on Planning Poker: while a story such as "Shelter problem briefs for teams" is being estimated, each member picks one card, and their vote stays hidden until the facilitator reveals it.

Once revealed, votes are shown as estimate cards beside each name. For a long or open-ended list, use a radio group or a select (the facilitator’s "Final points" is a select).

Anatomy

  1. Group label"Your vote"; it names the role="group".
  2. CardA button.estimate-choice with aria-pressed.
  3. ValueThe first span: the number, or "?", set large.
  4. Unit"points", or "Unsure" for the ? card, in caption type.
  5. Pressed markAccent-subtle fill, accent border and ring on the chosen card.

One scale only (a modified Fibonacci set plus Unsure). Staff watching a session see no picker at all: "Watching as Staff. You can follow the session live, but only workspace members vote."

Sizes

One size. Each card is at least 4.5rem wide and at least --target-comfortable tall; the value uses --font-size-3xl.

  • Pressed: pressing a card presses it and releases the others; pressing it again withdraws the vote (planning-poker/withdrawn): no card stays pressed, the status line says “You withdrew your vote” and the member shows as still choosing. Members can change or withdraw their vote until the reveal.
  • Disabled: after Reveal votes the deck locks, keeping your card pressed, through Re-vote or Set points.
  • Invalid (planning-poker/invalid): the server refused the vote because the votes were already revealed. No card is pressed, the group is aria-invalid="true" (every card takes the danger border) and the .field__error under the deck, which describes the group, says why. In Angular set error on ft-estimate-picker.
  • Failed to send (planning-poker/vote-failed): the vote never reached the server. The deck goes back to the saved vote and a danger alert above it says so (“Your vote is still 8 points”); pressing the card again retries.
  • The page’s loading, empty ("Start a session"), error and forbidden states replace the whole session, so the picker is not shown.

Responsive behaviour

  • The deck is a wrapping .cluster: eight cards fit on one row on desktop and wrap to two rows of four at 360px. Nothing scrolls sideways.
  • On phones the "Votes" list moves below the deck.

Theming

Your vote

Your vote

Role tokens only. In forced-colours mode the cards keep a system border, and the pressed card is still announced by aria-pressed.

Accessibility

Role and pattern

Toggle buttons (aria-pressed) in a role="group" named by "Your vote". Each card’s name is its visible text, such as "8 points" or "? Unsure", so the value is never conveyed by colour alone.

Keyboard

KeyAction
TabMoves through the cards in order.
Enter / SpacePresses or releases the focused card.

Announcements

The polite status line above the deck, "3 of 5 have voted. Votes stay hidden until Marcus reveals them.", updates as votes arrive. The reveal is announced in the session’s alert.

Motion and touch

The hover lift is removed under prefers-reduced-motion. Every card meets the 44px target.

Content

  • Label "Your vote". Values 1, 2, 3, 5, 8, 13, 21 with "points" under each; "?" with "Unsure".
  • Status: "3 of 5 have voted. Votes stay hidden until Marcus reveals them."
  • Never put words on the number line ("Small", "Huge"): the scale is points.

Code

<!-- Angular (components library) -->
<ft-estimate-picker label="Your vote" [options]="[1, 2, 3, 5, 8, 13, 21, '?']"
                    [value]="myVote" [disabled]="revealed" [error]="refusal"
                    (valueChange)="vote($event)" />

<!-- HTML -->
<div class="cluster" role="group" aria-labelledby="deck">
  <button class="estimate-choice" type="button" aria-pressed="true"><span>8</span>points</button>
  <button class="estimate-choice" type="button" aria-pressed="false"><span>?</span>Unsure</button>
</div>
Class / inputEffect
.estimate-choiceOne card. [aria-pressed="true"] is the vote; [aria-invalid] and :disabled are the other states.
options, value, disabledThe scale, the current vote (or none) and the lock after reveal.
errorWhy the server refused the vote; shown under the deck, describing the group, which is marked invalid.
valueChangeEmits the new vote, or null when it is withdrawn.
