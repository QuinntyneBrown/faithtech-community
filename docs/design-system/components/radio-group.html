Radio group

One choice from a few visible options: Public or Members only, In person or Online, which role to add. Native radios in a fieldset, drawn with the .choice row.

Overview

A radio group asks for exactly one of a few options that can all be seen at once: an event's format and visibility, who an announcement goes to, which role to add. Each option is a label.choice around a native radio, and the group is a fieldset with a legend.

  • Use it for two to six options where the difference matters enough to read: Public vs Members only, Scrum vs Kanban.
  • Don’t use it for one option. A single radio offers no choice; state the thing instead. Remove role names the one role in its title ("Remove Volunteer from Ruth Alvarez?") and shows a group only when the person holds several removable roles.
  • Use a select for a long or familiar list (event type, city).
  • Use a switch for one on/off setting.
  • Use a checkbox group when several options can be chosen at once, such as the member pickers (add workspace member, create workspace, start poker). It is the same .choice row with a square checkbox; see Variants.

Anatomy

  1. Legendlegend.field__label: names the question.
  2. RadioA native radio drawn with appearance: none: --size-icon-md circle, accent fill and on-accent dot when checked.
  3. Label.choice__text in --text-body.
  4. Description (optional)A small line in --color-fg-muted that says what the option means.

Checkbox group (several choices)

Members

Only people with a lead or volunteer role can be added.

The member pickers (add workspace member, create workspace, start poker) use the same .choice row around a native checkbox. .choice input[type="checkbox"] draws a square box (--radius-xs) with a check mark, so a multi-select never looks like the round single-select radio. In Angular: ft-checkbox-group with ft-checkbox children; its value is the list of checked values.
HTML
<fieldset class="stack"><legend class="field__label">Members</legend><p class="text-caption">Only people with a lead or volunteer role can be added.</p><label class="choice"><input type="checkbox" name="wm" value="marcus" checked><span class="choice__text">Marcus Lee<small>Event Lead</small></span></label><label class="choice"><input type="checkbox" name="wm" value="hannah"><span class="choice__text">Hannah Kim<small>Communications Lead</small></span></label></fieldset>

Sizes

Not applicable. One size at every width.

States

Hover and focus are forced with data-state.

UncheckedCheckedHoverFocusDisabledDisabled checkedInvalid

Both themes

  • Invalid: when nothing is chosen on submit, every radio in the group gets aria-invalid="true", the fieldset gets aria-describedby pointing at a .field__error ("Choose a role to add.").
  • Disabled is deliberately absent from the mocks: options a person cannot choose are left out and explained in a caption (see the Don’t below). The state exists so an option or group disabled through Angular forms still reads as unavailable.
  • Most groups have a default checked; only "Role" in add role starts empty, because there is no safe default.
Role
Choose a role to add.

Responsive behaviour

  • Options always stack vertically; they never sit side by side, so long labels and descriptions wrap cleanly at 360px.
  • The radio does not shrink (flex: none) and stays aligned with the first line of the label.

Theming

The radio reads --color-bg-surface and --color-border-strong unchecked, --color-fg-muted for the hover border, --color-accent and --color-fg-on-accent checked, and --color-bg-subtle with --color-border-default disabled. In dark the checked fill becomes the light violet and the dot turns dark, so the checked mark keeps its contrast.

Accessibility

Role and pattern

Native radios sharing a name, inside a <fieldset> with a <legend>. That gives the APG radio group behaviour for free. No ARIA roles.

Keyboard

KeyAction
TabMoves into the group, onto the checked radio (or the first one), and out again.
↓ / →Checks the next option.
↑ / ←Checks the previous option.
SpaceChecks the focused option if none is checked.

Focus

The shared focus ring around the radio circle.

Labelling

The legend is announced on entering the group; each option's label and description are its name, because the input sits inside the label. The legend stays visible, even when a section heading sits above the group, so sighted and screen reader users get the same name.

Contrast

Radio border on surface
Checked fill on surface
Dot on checked fill
Description on surface
Invalid border on surface
Focus ring on surface

Motion

Fill and border fade over --duration-fast; reduced motion makes it instant.

Touch

Each row is at least --target-min tall and the whole label is the target.

Content

  • The legend is a short noun: "Format", "Visibility", "Send to", "Role", "Method".
  • Option labels are short and parallel: "Public" / "Members only", "In person" / "Online".
  • Descriptions say the consequence: "Anyone with the link can see it and RSVP, even without an account".
  • Order options from most common to least, with the default first unless the order has meaning.
