Backlog tree

The backlog tree shows a workspace’s plan as Initiative, Epic, Story and Task, with each level folding open and closed.

Overview

The backlog tree shows a workspace’s work as a hierarchy: Initiative → Epic → Story → Task. Each branch has a disclosure button (aria-expanded, aria-controls) so people can fold away what they are not planning, and each item links to its work-item page. It also appears in the New work item and Start sprint dialogs to show where an item will sit. Added for FaithTech Community.

  • Use it for the Backlog view and for choosing a parent in context.
  • Use the Kanban board for status (To Do, In Progress, Done) and a table when people need to sort or compare fields.
  • It is a nested list of disclosures, not an ARIA tree widget; see Accessibility for why.

Anatomy

  1. Row and toggle.tree__row (--target-comfortable tall); on a branch it starts with button.tree__toggle, a chevron that points right when collapsed and down when expanded, named “Contents of <title>”.
  2. Type badge.badge--role coloured by level: info Initiative, warning Epic, success Story, neutral Task.
  3. Title linkOpens the work item.
  4. Meta.text-caption: child count, status, points or owner.
  5. Nested level.tree .tree: --space-6 indent with a 1px --color-border-default guide line.

  • Expanded/collapsed comes from the native open attribute; the browser exposes it as expanded/collapsed to screen readers.
  • Error and forbidden states replace the tree with the shared empty/error state; the tabs stay usable.

Responsive behaviour

  • Rows wrap (flex-wrap): at 360px the meta drops under the title instead of truncating it.
  • Indent is --space-6 per level; four levels at 360px still leave room for titles. Do not add a fifth level.
  • Branches start open on wide screens and on the initial load of the Backlog; on phones consider opening only the first initiative.

Theming

Rows read --color-fg-default for titles, --color-bg-subtle for hover and --color-border-default for guide lines; badges bring their own status tokens. All are theme-aware.

Accessibility

Role and pattern

Nested <ul> lists with disclosure buttons (the WAI-ARIA disclosure pattern: aria-expanded on the button, aria-controls naming the child list, which is hidden when collapsed), labelled aria-label="Backlog hierarchy". The ARIA tree pattern is deliberately not used: its single tab stop and arrow-key model hides the links inside rows and needs heavy script. Lists announce nesting level and item count already.

Keyboard

KeyAction
TabMoves through each branch’s toggle, then its title link, in order.
Enter / Space on a toggleExpands or collapses the branch.
Enter on a titleOpens the work item.

No nested interactive content

The title link never sits inside the control that toggles the branch. Earlier mocks put it inside <summary>, interactive content inside a button-like control: clicking the link could also toggle, and screen readers could announce only the summary. The toggle is now its own button beside the link. In Angular, ft-tree-item renders it for any item with children. See Do and don’t.

Content

  • Level names are fixed: Initiative, Epic, Story, Task. Never rename them per workspace.
  • Meta order: children count for branches (“2 epics”), else status · points (“In Progress · 8 pts”) or status · owner’s first name for tasks.
  • Orphans say so: “No initiative”, “No epic”. Unestimated stories say “not estimated”.

Class / attributeEffect
.treeList of rows; nested .tree gets the indent and guide line.
.tree__rowOne row (on li for leaves, on a div before the child ul for branches).
.tree__toggleBranch disclosure button: aria-expanded, aria-controls (the child list id), aria-label="Contents of <title>". The child list carries hidden when collapsed.
data-state="hover"Documentation only: forces the row hover background (--color-bg-subtle), the same as :hover.
data-state="focus"Documentation only: forces the focus ring.
