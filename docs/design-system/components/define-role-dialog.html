Define role dialog

Define or edit a role: name, description, the capability checklist and three switches, with invalid, forbidden, last-administrator, busy and failed states.

Overview

The define-role dialog creates a role (mode: "define") or edits one (mode: "edit", prefilled, primary “Save changes”). It composes a text field with a counter (Name, up to 60), a textarea (Description, up to 200), the capability checklist and three switches. The “Can be held for a {chapter}” switch is shown only when the dialog receives a chapter label. It is the wide dialog (.dialog--wide, 44rem) because the checklist has two columns.

Anatomy

  1. HeaderKey icon, “Define a role” or “Edit {role}”, and a description; edit mode says how many members hold the role.
  2. Name and descriptionRequired name with “{n} / 60”; optional description with “{n} / 200”.
  3. Capability checklistEvery catalogue entry with its description.
  4. OptionsShow on the team list; Can be held for a {chapter}; Oversight role.
  5. FooterCancel and Define role / Save changes.

  • Last administrator: editing the role that carries Administer the organisation so that no one would hold it shows “There must always be at least one administrator.” (409).
  • Failed: a danger alert “Role not saved”, the input kept, and the primary button reads “Try again”.
  • Success: the dialog closes and the Roles page raises “Role defined”.

Responsive behaviour

  • Below 40rem it is a bottom sheet with the footer pinned; the body scrolls.
  • From 40rem it is a centred panel; see Dialog.

Theming

Raised surface --color-bg-surface-raised on the backdrop in both themes, as every dialog.

Accessibility

Role and pattern

WAI-ARIA modal dialog through Angular CDK Dialog: focus trapped, the page behind inert, Esc closes unless busy, focus returns to the button that opened it.

KeyAction
TabMoves through fields, checkboxes and footer buttons.
EscCloses without saving (not while busy).
Enter on the primary buttonSaves.

Content

  • Name errors: “Enter a name.”, “Use 60 characters or fewer.”, “A role called {name} already exists. Choose another name.”
  • Options read as statements of what happens, not flags.

Do and don't

Tokens

The dialog tokens.

Code

In Angular: <ft-define-role-dialog> (DefineRoleDialogComponent, data: mode, role?, capabilities, chapterLabel?, submit), opened through DialogService (ADR 0005). Its submit callback resolves to null on success or to a message the dialog shows (a 400 field error, a 403 or 409 reason, or the failure with Try again).
