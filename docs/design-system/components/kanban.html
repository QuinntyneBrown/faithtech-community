Kanban board

The Kanban board shows partners or stories in columns by stage. People drag cards to move them, and every card also has a Move action that works from the keyboard.

WCAG 2.2 AAStatus: stableSections + lists, CDK drag + dialog

Overview

The Kanban board lays cards out in columns by stage. FaithTech uses it twice: the shared partner pipeline (Lead → In funnel → Confirmed), which every lead can update, and a workspace’s sprint board (To Do, In Progress, Done). Cards can be dragged between columns with a pointer, and every card also has a Move action that opens a dialog, which is the keyboard and screen-reader path and the one that is always available. Added for FaithTech Community.

  • Use it when the stage is the most important fact and people move things along a fixed flow.
  • Use a table or list for searching, sorting or bulk work; use the backlog tree for hierarchy.
  • Drag is an enhancement only. Never ship a board where dragging is the only way to change a stage.

Anatomy

  1. Column.kanban__column: a <section> labelled by its title, --color-bg-subtle, --radius-lg.
  2. Header.kanban__header: .kanban__title heading and a count .badge.
  3. Card.kanban__card: surface, 1px border, --shadow-1; name link + caption.
  4. Move actionSmall ghost <button type="button"> naming the card; it opens the Move dialog (in the mocks it names the dialog mock in data-href): “Move Lantern Foundation to another stage”.

Sizes

There is one size: one column on phones and three from 768px, because every workflow has exactly three stages (Lead, In funnel, Confirmed; To Do, In Progress, Done). Columns keep a 12rem minimum height so an empty column is still a visible target.

    • Empty board: when there are no partners at all, the board is replaced by the empty state “Start your partner pipeline” with Add partner. An empty column inside a populated board shows .kanban__empty.
    • Move dialog: default (radio group of stages, current marked, optional history note), busy (primary shows a pulse and “Move to Confirmed…”, Cancel disabled) and failed (alert “We couldn’t move the partner. Nothing was changed”). See dialog and radio group.
    • After a move the card appears in the new column, counts update, focus returns to the moved card’s Move action, and a polite announcement says “Kestrel Labs moved to Confirmed”.
    • Error and forbidden replace the board with the shared error state; a failed drag snaps the card back and shows a toast.

    Responsive behaviour

    • Below 768px columns stack in pipeline order; dragging is disabled on touch-only layouts and Move is the way to change stage.
    • Columns align to the top (align-items: start) so a short column does not stretch.
    • Card text wraps; names never truncate. Captions over two lines are too long.
    • The board never scrolls horizontally inside the page.

    Theming

    Columns use --color-bg-subtle and cards --color-bg-surface with --shadow-1, so cards lift off columns in both themes. Dragging raises to --shadow-3 with the focus ring; the drop zone uses --color-accent-subtle with a dashed --color-accent border. Motion (the 1° tilt) is static and has no transition, so reduced-motion needs nothing extra.

    Accessibility

    Role and pattern

    The board is a labelled region of <section> columns, each aria-labelledby its heading, each holding a <ul> of cards. Screen readers hear “Confirmed, list, 5 items”. Do not use aria-grabbed or aria-dropeffect: both are deprecated in ARIA 1.2 and not announced. The lifted card is styled with data-state="dragging" only, and the result of a move is announced in the board’s polite live region, which is on the page (empty) before any move so screen readers pick up the change.

    Keyboard alternative to drag (WCAG 2.5.7)

    Every card has a Move action that opens the Move partner (or, on a sprint board, Move story) CDK dialog: a radio group of stages with the current one marked, an optional note, and a primary button that names the result (“Move to Confirmed”). This is a single-pointer, keyboard and screen-reader path that does the same thing as dragging.

    KeyAction
    TabMoves through each card’s name link and Move action, column by column.
    Enter on MoveOpens the Move dialog with focus on the primary button.
    ↑ / ↓ in the dialogChanges the stage.
    EscCloses the dialog without moving; focus returns to Move.

    Focus

    Card links and Move show the global ring. While dragging, the card itself shows the ring so the lifted item is visible without colour.

    Labelling

    Each Move names its card (“Move Maple Street Church to another stage”) so a list of Move buttons is distinguishable. Column counts are plain text next to the heading.

    Touch

    Move is a 32px small button inside a card that is itself not a target; keep 8px between it and the name link.

    Content

    • Column titles are the stage names exactly: Lead, In funnel, Confirmed; To Do, In Progress, Done.
    • Card title is the partner or story name; the caption says who and why in under ten words (“Kwame Asante · venue for spring builders night”).
    • The Move dialog title names the card (“Move Kestrel Labs”) and the primary names the destination (“Move to Confirmed”).
    • Empty column copy says what is missing: “No partners at this stage yet”.
