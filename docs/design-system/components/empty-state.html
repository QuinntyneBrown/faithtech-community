Empty state

What a page shows when there is nothing to list yet, when a search or filter finds nothing, or when its data could not load: a round icon, a short title, one sentence, and the one thing to do next.

WCAG 2.2 AAStatus: stableComposition

Overview

Use an empty state in place of a list or a page body that has no content: Grace's contacts before the first one, the partner pipeline before any partner, a search with no results, a section that failed to load. Every empty, no-results and error page state in the mocks uses it.

  • Empty (.empty): nothing here yet, or nothing matches. Accent icon.
  • Error (.empty.empty--error, role="alert"): this part of the page didn't load. Danger icon and Try again.
  • Whole-page problems (not found, forbidden, server error, offline) use the same classes at page scale; see error page.
  • For a failed action, not a failed load, use an alert or a toast.

Anatomy

  1. Icon<span class="empty__icon">: 64px circle, accent-subtle (danger-bg for errors), 32px line icon, aria-hidden.
  2. Title.empty__title: an <h2> in the h3 style; says what is (not) here.
  3. Text.empty__text: one or two sentences, muted, 36ch max.
  4. Actions.empty__actions: one primary action, optionally one secondary. Left out when there is nothing the viewer can do (audit log, notifications).

  • Retrying: Try again becomes a busy button (aria-busy="true"); on success the real content replaces the whole block.
  • Examples here use <h3> because this page already has its headings; in the product the title is an <h2> under the page's <h1>.

Responsive behaviour

  • Centred at every width, with 48px top and bottom and 24px sides.
  • Text stops at 36 characters wide so it never runs the width of a desktop.
  • Two actions sit side by side and wrap, centred, when they don't fit.

Theming

The empty icon reads --color-accent-subtle with --color-fg-accent; the error icon --color-danger-bg with --color-danger-fg. Title and text read --color-fg-default and --color-fg-muted on the page canvas. All are theme tokens; nothing in the component changes between themes.

Accessibility

Role and pattern

Plain content: a heading, a paragraph and native buttons or links. The plain empty state has no ARIA role. The error variant carries role="alert" in the mocks so the failed load is announced when it replaces the skeletons. The small empty state is role="status", because it replaces a list while the person types in the search field above it; the title is then announced politely without moving focus.

Keyboard

KeyAction
TabMoves to the primary action, then the secondary.
Enter (and Space on buttons)Runs the action.

Focus

Focus does not jump to the empty state. After Try again fails, focus stays on the button.

Labelling

The icon is decorative. The title is a real heading, so it shows in the heading list. Try again is a <button> (it is an action); "New event" and "Clear search" are links (they go somewhere).

Content

  • Title says what is here: "No contacts yet", "No team yet in Toronto", "You’re all caught up". For no results, quote the query: "No one matches “xavier”".
  • Text says why it matters or what to try: "Contacts and your notes on them are private to you until they join." "Check the spelling, try fewer words."
  • The action is the next step as a verb: "Add your first contact", "New event", "Create your first workspace", "Clear search".
  • Errors start with "We couldn’t load…", never blame the member and never show codes in a section; the reference code belongs on the server error page.

Heading level

headingLevel is 2 by default, 3 inside a section, and 1 when the empty state is the whole page, as on an expired or invalid invite link, where the mock makes the empty title the page's h1.
