Stepper

Shows where someone is in a short wizard: "Step 2 of 4" and the step name, above one segment per step. It's read-only and sits between a wizard dialog's header and its body. First used by Create event hub (Event, Starting point, Sections, Done).

Overview

Use the stepper in a wizard with two to five steps, where each step asks one question. It tells people how far they've got and how much is left. It doesn't navigate: the footer's Back and Next buttons move between steps, so the segments aren't buttons.

  • In use: the Create event hub dialog (dialogs/create-event-hub/*), four steps.
  • Don't use it for a single form split into sections (use headings), or to show a known amount done (use progress).
  • The wizard's footer keeps "Save and finish later" on every step, so the stepper never has to mean "you can't leave yet".

Anatomy

  1. Count.stepper__count: "Step 2 of 4", muted label, tabular figures.
  2. Step name.stepper__name: the current step's name in the default text colour.
  3. Done segment.stepper__step--done, accent fill.
  4. Current segmentaria-current="step", accent fill.
  5. Upcoming segmentTrack colour --color-bg-subtle-hover. Each segment holds its step name, visually hidden.

One variant. The number of steps comes from the steps input; the segments share the width equally.

Sizes

One size: 4px segments (--space-1) with 4px gaps, under a label-sized status line. It fills the width of the dialog body.

  • Busy: while a step saves, the stepper doesn't change. The pressed button reads "Saving…" and the dialog is aria-busy (dialogs/create-event-hub/busy).
  • Failed or invalid: the stepper stays on the step, and the danger alert sits under it (failed, invalid).
  • Moving on: the current segment changes at once, with no animation.

Responsive behaviour

  • The segments always share the full width, so four steps fit at 320px.
  • The status line wraps the name under the count if a step name is long. Step names are short ("Starting point").
  • On phones the wizard dialog is a bottom sheet. The stepper stays at the top of the body, and the footer buttons wrap.

Theming

Segments read --color-accent (done and current) and --color-bg-subtle-hover (upcoming), the same pair as progress. The count reads --color-fg-muted, and the name reads --color-fg-default. In forced colours, segments get a CanvasText outline, and done and current segments fill with Highlight.

Accessibility

Role and pattern

The status line is plain text, so it's read in order after the dialog title. The dialog's aria-describedby points at it, so opening the wizard announces "Create event hub, dialog, Step 1 of 4 Event". The segments are an <ol> named "Progress" (the label input). Each item holds its step name, visually hidden, and done steps add ", done". The current item has aria-current="step".

Keyboard

KeyAction
TabNot a stop. Focus moves to the step's first field, or to Next on a step with no field.

Focus

When the step changes, the wizard moves focus to the new step's first control, and the status line is the first thing after it in reading order. The stepper never takes focus.

Contrast

Done or current segment on surface
Count on dialog
Name on dialog

The upcoming segment is decoration. The text "Step 2 of 4" carries the position, so position never depends on colour alone (WCAG 1.4.1).

Motion

None.

Touch

No targets.

Content

  • Count: "Step {n} of {total}".
  • Step names: a noun or short noun phrase in sentence case, at most three words ("Event", "Starting point", "Sections", "Done").
  • The question goes in the step's body ("Which event is this hub for?"), not in the stepper.
  • The list's name is "Progress" unless the wizard has a reason to say more.
