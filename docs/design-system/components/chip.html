Chip

A pill-shaped toggle for filtering a list in place: Upcoming, Past, Hackathons or Online on Events; All, Leads or Volunteers on Team.

WCAG 2.2 AAStatus: stableNative <button>

Overview

Use chips for a short row of filters above a list, where one tap narrows what is shown and nothing is saved. Use tabs to move between sections of a workspace, a select when there are more than five options (the epic filter), and a button for anything that changes data.

  • Filter chip (button with aria-pressed): one of a small set is on. Events and Team.
  • View chip (a with aria-current): switches between two views that are separate URLs, Tree and Sprint history on the backlog.

A pill that only labels something and cannot be pressed is a badge.

Anatomy

  1. Label--text-label, one or two words. The accessible name.
  2. Pill32px tall (--control-height-sm), 12px side padding, --radius-full, 1px --color-border-strong. Accent tint and border when pressed.

Variants

Filter chips

From Events and Team. Pressing one chip un-presses the others and refilters the list below; the result count is announced politely.
HTML
<div class="cluster cluster--between filter-bar">
  <div class="cluster" role="group" aria-label="Filter events">
    <button class="chip" type="button" aria-pressed="true">Upcoming</button>
    <button class="chip" type="button" aria-pressed="false">Past</button>
    <button class="chip" type="button" aria-pressed="false">Hackathons</button>
    <button class="chip" type="button" aria-pressed="false">Online</button>
  </div>
  <!-- City select -->
</div>

View chips

TreeSprint history
From Backlog. Each view is its own page, so these are links; the current one carries aria-current="page". The pressed look comes from the aria-pressed selector, which is a styling hook only (see Sources).
HTML
<nav class="cluster" aria-label="Backlog view">
  <a class="chip" href="default.html" aria-current="page" aria-pressed="true">Tree</a>
  <a class="chip" href="sprints.html">Sprint history</a>
</nav>

Sizes

One size, 32px tall. Chips sit in a .cluster with 12px between them, which keeps neighbouring targets apart.

States

Pointer and focus states are forced with data-state; real pages get them from :hover, :focus-visible, aria-pressed and disabled.

Both themes

  • Pressed: accent tint, accent border, accent label.
  • Disabled: native attribute at 50% opacity, used only while the list is loading so a second filter cannot race the first.
  • A filter that matches nothing stays pressed; the list shows its no-results empty state ("No volunteers match").

Responsive behaviour

  • Chips wrap onto new lines inside the .cluster; they never scroll sideways and never shrink.
  • Labels do not wrap inside a chip. At 360px the four event filters fit on one line or wrap to two.

Theming

Unpressed chips read --color-bg-surface, --color-border-strong and --color-fg-default; hover adds --color-bg-subtle. Pressed reads --color-accent-subtle, --color-accent and --color-fg-accent. All are semantic tokens, so both themes come for free.

Accessibility

Role and pattern

Filter chips are native <button type="button"> with aria-pressed (APG toggle button), inside role="group" with an aria-label such as "Filter events". View chips are links inside a labelled <nav>, with aria-current="page" on the current view.

Keyboard

KeyAction
Tab / Shift+TabMoves chip to chip; every chip is a tab stop.
Enter / SpacePresses a filter chip. Enter follows a view chip.

Focus

The shared 2px focus ring with 2px offset, at least 3:1 on the pressed tint. After filtering, focus stays on the chip; the list updates below and a polite live region announces "4 upcoming events".

Labelling

The visible text is the name: "Hackathons, toggle button, not pressed". The group label gives the context.

Motion

Background colour fades over --duration-fast, zeroed under prefers-reduced-motion.

Touch

32px tall with 12px between chips: above the 24px minimum, and the gap keeps a thumb from pressing two.

Content

  • One or two words, sentence case, plural for groups: "Leads", "Volunteers", "Hackathons".
  • Put the default first ("Upcoming", "All") and keep it pressed on first load.
  • No more than five chips in a group; more than that is a select.

The chip rule is inherited from Shelfie unchanged. Resolved: the filter rows on Events and Team are now .cluster.cluster--between.filter-bar rows holding a role="group" chip cluster labelled "Filter events" or "Filter team", with no inline margin. Drift: the backlog view chips are links carrying aria-pressed, which is not valid on a link and is read by no screen reader, and they lack aria-current. The suggested fix is to add .chip[aria-current="page"] to the pressed selector in components.css: .chip[aria-pressed="true"], .chip[aria-current="page"], .chip[data-state="selected"] { … }.
