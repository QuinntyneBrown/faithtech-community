Description list

A description list shows labelled facts about one thing, like a contact’s email and organisation or where an event happens.

WCAG 2.2 AAStatus: stableNative <dl>

Overview

A description list shows labelled facts about one thing: a contact’s email, phone and organisation; an event’s place, format and host; a partner’s stage and main contact; a work item’s status and points. It is a semantic <dl> with each pair grouped in a <div>. Added for FaithTech Community.

  • Use it for read-only facts with short values. Editing opens a dialog or the edit screen; the list itself never becomes a form.
  • Use a table when several records share the same fields, and a list for a set of items.

Anatomy

  1. Termdt: --text-label in --color-fg-muted, a 6 to 9rem column.
  2. Descriptiondd: body text, overflow-wrap: anywhere so emails and addresses break.
  3. Pair group<div> inside .facts, a two-column grid with --space-3 gaps.

  • A missing optional value shows “Not added” in muted text rather than dropping the row, so the layout does not shift between contacts.
  • Loading uses skeleton lines inside the containing card; errors replace the whole card with an error state.

Responsive behaviour

  • The two columns hold at 360px; the term column shrinks to 6rem and long values wrap.
  • Emails, URLs and addresses break anywhere instead of overflowing the card.
  • In the two-column .split layout the list sits in the side column on wide screens and below the main content on phones.

Theming

Only --color-fg-muted (terms) and the inherited body colour (values) are read, so the list follows the surrounding surface in both themes.

Accessibility

Role and pattern

A native <dl>; grouping <div>s are valid HTML and keep pairs together for assistive tech. Screen readers announce term and description in order.

Keyboard

KeyAction
TabReaches only links inside values (email, partner page); the list itself is not focusable.

Labelling

The list is labelled by its card heading (“Contact details”, “Partner details”). Do not repeat the term inside the value.

Content

  • Terms are short nouns in sentence case: Email, Phone, Organisation, City, Added; Where, Format, Hosted by, Visibility, Going.
  • Values are plain facts. Dates follow the product format (“Thu 18 Sep”), with who did it when it matters (“by you”).
  • Make emails mailto: links; keep phone numbers as text unless the app offers calling.
