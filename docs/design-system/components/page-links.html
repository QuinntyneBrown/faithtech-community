Page links

The two sections under a Notes page's blocks: Pages inside (its child pages) and Linked from (the pages that link to it). Both list only pages the viewer may open.

Overview

Pages nest and link to each other; these sections make both directions findable from the page itself. ft-page-links renders one section: a heading, a list of pages, each with its emoji icon tile and title (or an empty line), and an optional action after the list. The server decides what is listed: pages the viewer may not open, and archived pages, are neither named nor counted (L2-090 AC5, L2-091 AC2).

  • Pages inside: the page's non-archived children, most recently edited first, with New page inside for the owner. With no children the owner sees "No pages inside yet." and the button; everyone else sees no section at all.
  • Linked from: the non-archived pages that link here. With none it reads "No pages link here yet." for everyone.
  • Do not use it for search results or the Notes list; those are the list and search results.

Anatomy

  1. Heading.backlinks__title: an <h2> in the app ("Pages inside", "Linked from"), --text-h4; and the section is a region named by the same text (aria-label).
  2. Empty text.backlinks__empty: "No pages inside yet." or "No pages link here yet." when nothing is listed. There is no count.
  3. Action"New page inside", a small secondary button projected after the list, for the owner (and a System Admin) on Pages inside only.
  4. Icon tileft-icon-tile with emoji, size sm (32px); the default page icon when the page has none. Decorative.
  5. Row.list__item with the title as the link (/notes/{id}); "Private page" is plain text. No meta line.

In the editor the section sits under the blocks as .block-editor__section, aligned with the text column and separated by a hairline rule.

Responsive behaviour

  • Full width of the editor column at every breakpoint; at XS the two sections stack under the blocks, Pages inside first.
  • The heading row wraps: New page inside drops under the heading on a narrow phone.
  • Long titles wrap within the row; nothing scrolls horizontally.

Theming

Inherits the list and card tokens (--color-bg-surface, --color-border-default, row hover --color-bg-subtle), the emoji tile's --color-bg-subtle, and the muted empty text --color-fg-muted. The section rule is --color-border-default. Emoji keep their own colours in both themes.

Accessibility

Role and pattern

Each section is a <section> labelled by its heading, so it appears as a region in a screen reader's landmarks list; the pages are a real <ul>. In the app the headings are <h2>, at the same level as Heading 1 blocks, after the page's blocks.

Keyboard

KeyAction
TabNew page inside, then each page title link in order.
EnterOpens the page, or creates a new page inside and opens it with focus in its title.

Labelling

Icon tiles are hidden; the link text is the page's title ("Untitled" for an empty one). Hidden pages are never mentioned, not even as "and 2 more".

Code

<ft-page-links heading="Pages inside" [pages]="p.children" emptyText="No pages inside yet.">
  @if (editable()) {
    <ft-button size="sm" [loading]="creating()" (click)="newPageInside()">
      <ft-icon name="add" /> New page inside
    </ft-button>
  }
</ft-page-links>
<ft-page-links heading="Linked from" [pages]="p.backlinks" emptyText="No pages link here yet." />
// inputs: heading (required), pages: readonly PageLinkItem[] = { id: string | null, title, icon: string | null },
//         emptyText, basePath = '/notes/'; the projected content (an action) follows the list

The section is a region named by its heading (aria-label) with an h2; pages are ft-list-items (label = title, link to basePath + id) with a small ft-icon-tile showing the emoji, or the notes glyph when there is none. An item with no id ("Private page") is not a link. There is no count badge and no meta line. The page decides when to show "Pages inside": for the owner (with "New page inside") or when there are children; "Linked from" is always shown.
