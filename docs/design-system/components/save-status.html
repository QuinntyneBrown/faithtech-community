Save status

A short line beside a Notes page's actions that says what autosave is doing: "Saving…", "Saved", or "Couldn’t save" with Retry.

Overview

A Notes page has no Save button: the editor saves the whole page 800 ms after the last change, one save at a time (L2-086 AC8). The save status is the only sign of that work, so it must be honest and quiet: it says "Saving…" while a save is in flight, "Saved" when it succeeds and "Couldn’t save" with Retry when a network or server error stops it. Between a change and the save it shows nothing (unsaved), so it never claims "Saved" for edits that are not stored yet. Edits stay in the editor either way.

  • Use it wherever content saves itself without a submit, today the block editor's page.
  • Do not use it for a form with a Save button (the button's busy state and a toast do that) or for a conflict or lost access: those are banners (see Autosave and edit conflicts).

Anatomy

  1. IndicatorA spinner drawn by .save-status--saving::before, the check icon (--color-success-icon) for Saved, or the alert icon (--color-danger-icon) for Couldn’t save. Decorative.
  2. Label.save-status: --text-body-sm, muted; danger and medium weight when it failed. 24px minimum height so it lines up with the page's buttons.
  3. RetryA small secondary button, only after a failure. It resends the whole page; so does the next change.

Responsive behaviour

  • Sits in the page's action row after the visibility badge; at XS the row wraps and the status stays on the first line while Share collapses into More actions.
  • The text never truncates; it is at most two words plus Retry.

Theming

Muted text --color-fg-muted; the spinner uses currentColor; Saved's check is --color-success-icon; failure uses --color-danger-fg and --color-danger-icon. All are role tokens with dark values; the line sits on --color-bg-canvas or --color-bg-surface.

Accessibility

Role and pattern

A live region. "Saving…" and "Saved" are announced through a polite role="status"; "Couldn’t save" through an assertive role="alert" (L2-099 AC6). The component keeps two regions in the DOM from the start (an empty alert region and the status region) so announcements are not dropped, and only changes their text.

Keyboard and focus

The status itself is not focusable. Retry is a normal button in tab order after the status; activating it keeps focus on it until the status changes, then focus moves back to where the caret was. Focus never jumps to the status on failure.

Labelling

The text is the label; icons are aria-hidden. Because the region is polite, "Saving…" and "Saved" wait for the screen reader to finish what it is reading and never interrupt typing; "Couldn’t save" interrupts, because the person's work is at risk.

Colour

The state is always in words; icon and colour only reinforce it.

Motion

The spinner turns at half --duration-loop. Under prefers-reduced-motion it stops and shows as a still, faded ring.

Content

  • Exactly "Saving…" (with the ellipsis character), "Saved" and "Couldn’t save" (curly apostrophe), and "Retry".
  • No times ("Saved 2 minutes ago") and no exclamation marks; the meta line under the title carries the edited time.

Code

<ft-save-status [state]="saver.state()" (retry)="saver.retry()" />
// state: SaveState = 'unsaved' | 'saving' | 'saved' | 'failed'  (default 'saved')
//   unsaved  nothing shown: changes wait for the next save
//   saving   "Saving…" with a spinner, in the polite role="status" region
//   saved    check icon + "Saved", in the polite region
//   failed   error icon + "Couldn’t save" in the assertive role="alert" region, and a ghost sm "Retry" button
// retry: output<void>()

The notes library owns the autosave loop (800 ms after the last change, one save in flight, changes made meanwhile sent next with the new version) and passes its state; a change sets unsaved until the save starts. Both live regions are always rendered (empty when not in use) so screen readers announce changes. After a 409 or 403 the state stays failed while the page's conflict or access banner explains it. The built component uses .ft-save-status__text, __text--failed and __spinner; the mock classes below draw the same states.
