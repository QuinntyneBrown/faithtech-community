File row

One file in an upload: its type icon, name, type and size, then its progress and outcome. Rows sit in a flush card list above the drop zone.

Overview

Use file rows to show the files a member has chosen before and while they upload: in Add a resource (single, batch, busy, failed, invalid) and in Edit a resource (the current file and its replacement). A finished resource in a list is a list row with a type icon, not a file row.

  • Ready: chosen, not yet sent; offers Remove.
  • Uploading: determinate progress with a percentage.
  • Uploaded: 100% and the success badge "Uploaded".
  • Failed: the danger badge "Didn’t upload" and Remove; retried by the dialog's "Try N again".
  • Refused: the danger badge "Can’t add" (wrong type, too big or content that doesn’t match) and Remove.
  • Current / new (edit): the current file with Replace file, or the replacement marked new.

Anatomy

  1. Type iconA small type icon tile (.icon-tile--sm, 32px), decorative.
  2. File name--text-label, truncated with an ellipsis; the full name is in the accessible names of Remove and the progress bar.
  3. Meta--text-body-sm muted: "DOCX · 640 KB" while choosing, "Logo · 208 KB" in a batch (the guessed type).
  4. Progress.progress-row with role="progressbar" named "Uploading {file name}" and the percentage label.
  5. TrailingRemove (ghost icon button, "Remove {file name}"), a status badge, or Replace file.

Sizes

One size: rows are at least 56px tall with the 32px icon tile. The trailing icon button is 32px (.btn--sm) with a 44px hit area from the row padding.

  • While a batch uploads, the dialog's status line says "Uploading 3 of 6…" so screen-reader users hear the overall progress without every row speaking.
  • Remove is hidden while a row uploads and once it has uploaded; an uploaded file is already a resource.
  • A refused row stays until removed; the submit stays disabled meanwhile.

Responsive behaviour

  • The name truncates; the meta, progress and badge wrap under it at XS.
  • Rows never scroll sideways; the badge keeps its own width.

Theming

Rows read the list tokens; the badge and progress read their own semantic tokens. Nothing is theme-specific.

Accessibility

Role and pattern

Rows are <li> in a <ul>. The progress bar is role="progressbar" with aria-valuenow and the name "Uploading {file name}". Badges are text, not colour alone.

Keyboard

KeyAction
TabMoves to each row's Remove or Replace file.
Enter / SpaceRemoves the file; focus moves to the next row's Remove, or to the drop zone after the last.

Labelling

Remove is named "Remove {file name}" so a list of Removes is distinguishable.

Content

  • Show the file's own name, never a rewritten one.
  • Meta is "EXT · size" while choosing one file, "{guessed type} · size" in a batch.
  • Status words: "Uploaded", "Didn’t upload", "Can’t add"; the reason is in the field error, not the badge.
