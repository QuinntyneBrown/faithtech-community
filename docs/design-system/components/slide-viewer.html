Slide viewer

Shows a deck one slide at a time, with Previous and Next, a “Slide n of m” line and a strip of thumbnails to jump to any slide. The left and right arrow keys move when the viewer has focus. A slide that is a PDF shows its first-page thumbnail and one link, “Open the slides (PDF)”.

Overview

Use the slide viewer when people page through an ordered set of images that belong together: the event hub’s Slides section (L2-182). Each slide is a resource the hub names; visitors load it through the hub’s file link, never through Resources.

  • In use: the Slides section of the hub page (pages/hub-page/hackathon, slides-viewer, slides-pdf) and the Slides wizard’s preview.
  • For photos someone manages (feature, describe, delete), use the photo gallery. For choosing photos to upload, use the picture list.
  • It never advances by itself: no autoplay, no timer.

Anatomy

  1. Stage.slide-viewer__stage: a 16:9 figure that holds the current slide, letterboxed (object-fit: contain) so nothing is cropped.
  2. Previous and NextIcon buttons (.btn--icon), named “Previous slide” and “Next slide”.
  3. Status.slide-viewer__status: “Slide 18 of 52” (label type, tabular numbers) over the slide’s title (muted, one line, truncated). A polite live region.
  4. Thumbnails.slide-viewer__thumbs: a toolbar of .slide-viewer__thumb buttons that scrolls sideways; the current one has aria-current="true" and an accent ring.

Images, one per slide, in the order the organiser set.

File (a PDF)

.slide-viewer--file: a PDF is not paged inside the viewer. The stage shows its first-page thumbnail and a primary link opens the file in a new tab. A deck of one PDF leaves out the bar and the thumbnails; a PDF among image slides shows the same stage and link at its place in the deck, with the bar and thumbnails as usual.

Sizes

One size: the viewer fills its column, and the stage keeps 16:9. Thumbnails are 6rem wide (16:9), with 8px (--space-2) between them. Previous and Next are 44px icon buttons.

Responsive behaviour

  • Phone (360px): the stage fills the column; the strip shows about three thumbnails and scrolls sideways inside itself, never the page. The current thumbnail is scrolled into view.
  • Tablet and desktop: the viewer stays inside the hub’s reading column (form-width--lg), so a slide never grows past 40rem wide.
  • Touch: a horizontal swipe on the stage moves one slide. The title truncates to one line; the count never does.

Theming

The stage and thumbnails sit on --color-bg-subtle with a --color-border-default hairline, so a slide with a white background still has an edge in the light theme. The current thumbnail ring is --color-accent; hover darkens the border to --color-border-strong. Slide images are never tinted in the dark theme.

Accessibility

Role and pattern

The WAI-ARIA carousel pattern without rotation: the viewer is a region with aria-roledescription="carousel" and a name (“Slides”); the stage is a group with aria-roledescription="slide" named “18 of 52”. Each slide image’s alt is “Slide 18: ” plus the resource’s title. The status line is a polite live region, so moving says “Slide 19 of 52, Three tracks” once. Thumbnails are a toolbar (“Jump to a slide”) of buttons with a roving tab stop; each thumbnail’s image is decorative and the button is named “Slide 19: Three tracks”.

Keyboard

KeyAction
TabThe viewer, then Previous, Next and the current thumbnail: four stops however long the deck.
← / → on the viewerPrevious and next slide. Nothing happens past either end.
Home / End on the viewerFirst and last slide.
← / → in the thumbnailsMove focus along the strip; Enter or Space shows that slide.

Disabling Previous on slide 1 keeps focus on the viewer, never on a disabled button: when a button becomes disabled while focused, focus moves to the viewer.

Motion

Slides change without a transition. The strip scrolls smoothly to the current thumbnail only when prefers-reduced-motion is not set.

Content

  • Count: “Slide 18 of 52”, never “18/52”.
  • Title: the resource’s title, as the organiser wrote it.
  • PDF link: exactly “Open the slides (PDF)”.
  • Help line above the viewer: “Use the left and right arrow keys, or pick a thumbnail.”

Code

<ft-slide-viewer
  label="Slides"
  [slides]="slides"            <!-- { src, thumbnailSrc, title, kind: 'image' | 'pdf' }[] -->
  [(index)]="current"
  pdfLabel="Open the slides (PDF)" />
Input / outputEffect
labelAccessible name of the region (required).
slides: SlideViewerSlide[]The deck in order: image URL, thumbnail URL, title (the alt and the status line) and kind. A 'pdf' slide renders the file variant at its place (required).
index (model)The current slide, zero-based; two-way bindable. Defaults to 0.
pdfLabelThe PDF link’s text. Defaults to “Open the slides (PDF)”.
pdfMetaOptional muted line beside the link (“SoCal Hackathon slides · PDF · 18.4 MB”).

The component owns the keyboard map, the roving tab stop in the strip, scrolling the current thumbnail into view, the live status and swipe. It makes no HTTP calls: the events library passes hub file URLs.
