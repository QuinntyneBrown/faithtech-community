Notification panel

The bell tells a member something happened while they were away, like a contact signing up or an event being cancelled, and opens a short list of notices.

Overview

The notification panel is the in-app half of FaithTech notifications: a bell in the top bar with an unread count, a popover with the latest notices, and the full Notifications page that uses the same .notice-list. Notices tell a lead that a contact signed up, an event was cancelled, an invite was accepted, an announcement arrived, or (in workspaces) that someone assigned them a story. Added for FaithTech Community.

  • Bell + panel (.bell-anchor, .bell-panel) for a quick glance from any page; it shows the latest few and links to See all.
  • Notice list (.notice-list in a .card--flush) on the Notifications page for the full history.
  • Use a toast for confirmation of the person’s own action, and an alert or banner for something that blocks the current page. See the notifications pattern.

Anatomy

  1. Bell triggerGhost icon button; the count badge is aria-hidden and the number is in the button’s name.
  2. Panel header.bell-panel__header: title and Mark all read.
  3. Unread notice.notice--unread: --color-accent-subtle wash and an accent dot; the meta also says “Unread” so colour is not the only cue.
  4. Read notice.notice: avatar initials, sentence with at most one link, .notice__meta time.
  5. Footer.bell-panel__footer: See all link to the Notifications page.

  • Unread: wash + dot + the word “Unread” in the meta. Opening a notice’s link marks it read; Mark all read clears every wash and the badge.
  • Empty: the panel shows “You’re all caught up”; Mark all read is removed because there is nothing to mark.
  • Loading and error exist on the Notifications page (skeleton rows, .empty--error with Try again). The bell keeps its last known count while the panel loads.
  • Count over 9 shows the number; the badge never shows “9+” while the accessible name gives the exact count.

Responsive behaviour

  • Below --layout-breakpoint-md the panel is as wide as the viewport minus the page margins and stays anchored to the right edge under the bell.
  • The panel shows at most the five latest notices; longer history lives on the Notifications page.
  • Notice text wraps; it never truncates, because the sentence carries the meaning.
  • On phones the bell stays in the top bar; it is not duplicated in the bottom tab bar.

Theming

The panel is a raised surface (--color-bg-surface-raised, --shadow-3, --z-dropdown). Unread notices use --color-accent-subtle with an --color-accent dot; both are theme-aware, so the wash stays subtle in dark mode and body text keeps its contrast.

Accessibility

Role and pattern

The bell is a <button type="button" aria-haspopup="dialog" aria-expanded>, never a link, that toggles a non-modal panel with role="dialog" and aria-label="Notifications", built on the CDK Overlay. While the panel is open the button has aria-controls pointing at it; when closed the panel is not in the DOM, so aria-controls is dropped. In static mocks the button opens the open-bell mock through data-href. Notices are a plain list; each has at most one link plus the panel’s own buttons.

Keyboard

KeyAction
Enter / Space on the bellOpens the panel and moves focus to its first focusable element (Mark all read).
TabMoves through Mark all read, each notice link and See all.
EscCloses the panel and returns focus to the bell.
Click or focus outsideCloses the panel.

Announcements

New notices arriving while the page is open update the bell’s name (“Notifications, 4 unread”) and are announced once through a polite live region in the shell, not by moving focus.

Labelling

The count is in the bell’s aria-label; the visual badge is aria-hidden. Avatars are decorative (aria-hidden) because the sentence names the person.

Contrast

Touch

The bell is a 40px icon button; notice links are inline text, so the whole notice row is not a target and nothing is nested.

Content

  • Lead with the person, then what happened, then the object as the link: “Esther Nakamura cancelled Austin Faith & AI Panel”.
  • One sentence, past tense, no exclamation marks. Name roles exactly (“joined as Volunteer”).
  • Time in the meta follows the mocks: “Today, 11:42 am”, then “Mon 20 Oct” for older days.
  • Private-contact notices (“he’s one of your contacts”) only reach the lead who owns the contact.
  • Empty copy: “You’re all caught up” + what will appear here.
