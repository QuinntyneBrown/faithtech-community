Checklist row

One row for each thing someone still has to finish, with its state shown three ways: an icon, a badge and the text of the badge. The event hub home uses one row per section: Hero is Ready, Agenda needs info, Giving is hidden.

Overview

Use checklist rows inside an ft-list when a page is a to-do list of parts that each have a state, and the person works through them in any order. Pair the list with a progress line that counts the ready rows ("3 of 6 sections ready").

  • In use: the Sections card on the event hub home (pages/event-hub/*).
  • The trailing [actions] slot is empty in slice 41. Slice 42 adds Fill in and Edit buttons that open each section's wizard.
  • For a list of people or records, use the plain list item. To choose options, use a checkbox group.

Anatomy

  1. State icon.checklist-row__icon: a check (Ready), an exclamation mark (Needs info) or a crossed-out eye (Hidden). Decorative.
  2. Title.checklist-row__title, label type.
  3. One line.checklist-row__text: what the part is for, in muted small body text.
  4. End.checklist-row__end: the state badge, then the [actions] slot.

Variants

Three states set by state: 'ready', 'needs-info' and 'hidden'.

  • Hero

    The event’s name, date, place and RSVP button at the top.

    Ready
  • Agenda

    The day’s schedule, with what’s happening now highlighted.

    Needs info
  • Giving

    How to give, from your organisation’s giving link.

    Hidden
Ready uses a success badge and icon, Needs info a warning badge and icon, and Hidden a neutral badge with the title muted.

Sizes

One size. Padding is 12px by 16px (--space-3, --space-4), the same as a list item, so checklist rows and list items line up in a flush card.

The row itself isn't interactive, so it has no hover, focus or pressed state. Buttons in the actions slot have their own states.

Responsive behaviour

  • The body takes at least 14rem. When the end (badge and actions) doesn't fit beside it, the end wraps onto its own line and sits on the right (pages/event-hub/default at 360px).
  • Titles and lines wrap; nothing truncates.

Theming

Icons read --color-success-icon, --color-warning-icon and --color-fg-subtle. Badges use the badge success, warning and neutral variants. The hidden title reads --color-fg-muted. Dividers read --color-border-default.

Accessibility

Role and pattern

The host element has role="listitem" inside ft-list (a <ul>), and the list is named for what it holds ("Sections"). A screen reader reads each row as "Agenda, The day’s schedule…, Needs info", so the badge text carries the state. The icon is aria-hidden.

Keyboard

KeyAction
TabSkips the row; it reaches only buttons in the actions slot.

Contrast

Ready icon on card
Needs info icon on card
Hidden title on card
One line on card

The state is never shown by colour alone: the badge says it in words and each icon has its own shape (WCAG 1.4.1). The hidden icon is decorative, so it isn't held to 3:1.

Touch

Only buttons in the actions slot are targets, and they're at least 44px.

Content

  • Title: the part's name, in sentence case ("Submission and feedback").
  • One line: what the part does for the visitor, in one sentence ending with a full stop.
  • Badges: exactly "Ready", "Needs info" and "Hidden".

Code

<ft-list label="Sections">
  @for (section of hub.sections; track section.id) {
    <ft-checklist-row [label]="section.title" [description]="section.description" [state]="stateOf(section)">
      <!-- slice 42: <ft-button actions size="sm">Fill in</ft-button> -->
    </ft-checklist-row>
  }
</ft-list>
Input / slotEffect
labelTitle (required).
descriptionThe one line under it.
state: 'ready' | 'needs-info' | 'hidden'Icon, badge text and variant, and muting for hidden (required).
[actions]Trailing slot after the badge.
