Error page

When a whole page cannot be shown, FaithTech replaces its body with a round icon, a plain heading, one or two sentences and a way back to somewhere useful. Nobody should feel they broke something.

Overview

Use an error page when the route itself fails. There are exactly four (L2-048). When only one section of a page fails, keep the page and use an error empty state in that section instead.

  • Not found (search icon): a link is old, or the event or contact was removed.
  • Forbidden (lock icon): the page needs a role the member doesn't have, such as a Volunteer opening People and roles or the admin audit log.
  • Server error (alert icon): the server failed. Shows a reference to quote to support.
  • Offline (no-signal icon): no connection; unsaved typing is kept. The “No connection” warning banner sits above it.

The page keeps the normal top bar (brand, primary navigation, search, bell), so navigation still works. Private contacts that belong to another lead also answer with Not found, not Forbidden, so their existence is not revealed.

Anatomy

  1. Icon.empty__icon: 64px accent circle with a 32px line icon; decorative.
  2. HeadingThe page's <h1 class="empty__title">.
  3. Explanation.empty__text: what probably happened and what to do. The server error adds a .text-caption reference line.
  4. Way back.empty__actions: Go home, or Try again for server error and offline.

Variants

Four pages, one layout. The examples use <h3>; in the product the heading is the page's <h1>.

Sizes

One size: the empty state inside a .error-page wrapper, which adds 48px (--space-12) above it so the message sits in the upper middle of the screen.

States

Each error page is a single state. Its buttons carry the interactive states; Try again becomes a busy button while it retries.

Responsive behaviour

  • Centred in main at every width; the text stops at 36ch.
  • On phones the top bar collapses as usual; the message and its single action stay centred.

Theming

Reads the same tokens as the empty state: --color-accent-subtle and --color-fg-accent for the icon, --color-fg-default and --color-fg-muted for the words. All four pages use the accent icon, not the danger one. Nothing is theme specific.

Accessibility

Role and pattern

A normal page: skip link, top bar, main with one <h1>. The document <title> names the problem ("Not found · FaithTech") so it is announced on load. The server answers with the matching HTTP status (404, 403, 500).

Keyboard

KeyAction
TabSkip link, top bar, then the page action.
Enter, SpaceRuns Try again; follows Go home.

Focus

On a client-side route change to an error page, focus moves to the <h1> (with tabindex="-1") so the heading is read first.

Labelling

The icon is aria-hidden. The heading carries the whole message in words. The reference is plain text so it can be read out or copied.

Content

  • Headings are plain: "We can’t find that page", "You don’t have access to this", "Something went wrong on our side", "You’re offline".
  • Say it is not the member's fault and what is safe: "It’s not you." "Anything you were typing is still here."
  • Forbidden says who can help: "Your City Lead can add one if you need it." Never name the missing role's holders or reveal what the page contains.
  • Only the server error shows a code, labelled "Reference:".
