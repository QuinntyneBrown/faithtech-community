Repeat list

An editable, ordered list of row cards in a wizard step: a hub’s Rules, Tracks, Parking options, Create Cycle stages, Demo format segments, Judging criteria, Worship songs and What to bring. Each row is a group named by its heading (“Rule 01”), with Move up, Move down and Remove, then the row’s own fields.

Overview

Use a repeat list when a person builds an ordered set of small records in a dialog, each with a few fields, and the order matters to visitors.

  • In use: the hub wizards dialogs/hub-rules, hub-parking, hub-tracks, hub-process, hub-demo-format, hub-judging, hub-worship and hub-what-to-bring.
  • An “Add a rule” button sits under the list; the wizard owns adding rows.
  • For reordering saved records with a drag handle and a row menu (chapters, taxonomies), use the reorderable list. For read-only rows, use the list.

Anatomy

  1. Headingh4.overline: the row’s place, “Rule 01”. It names the row’s group.
  2. Actions.list__actions: three ghost, small, icon buttons: Move up, Move down, Remove.
  3. FieldsThe row’s form fields, projected as content (often in a .grid--auto).

Variants

One variant. The list is an <ol> on a flush card; each row is a .list__item whose body is a .stack group.

  1. Rule 01

  2. Rule 02

The Rules wizard. Move up is disabled on the first row and Move down on the last.

Sizes

One size. Rows pad 12px by 16px; the actions are small icon buttons with 4px between them; the heading and the fields sit 16px apart.

  • Invalid: a row’s field shows its own field error; the step’s error summary links to it.
  • Busy: while the wizard saves, the whole dialog is busy; the row adds nothing.

Responsive behaviour

  • The heading and the actions stay on one line at every width; the heading never wraps.
  • A row’s fields sit side by side in .grid--auto when there is room and stack on a phone.

Theming

The list is a flush card on --color-bg-surface with --color-border-default hairlines between rows; the heading is --color-fg-muted overline type. Both themes follow from the tokens.

Accessibility

  • The list is an <ol> named by the wizard (“Rules”), so position is announced.
  • Each row body is a group labelled by its heading, so a field reads as “Rule 02, Title”.
  • The buttons name the row: “Move Any stack up”, “Remove Any stack”. A row with no title yet uses its heading: “Remove Rule 03”.
  • After a move, focus stays on the moved row’s same button; when that button becomes disabled (the row reached an end), focus goes to the row’s other move button, never to the page.
  • After Remove, the wizard moves focus to the next row’s first field, or to “Add a rule” when none is left.
KeyAction
TabThe row’s enabled buttons, then its fields, in order.
Enter / SpaceMoves or removes the row.

Content

  • Heading: the thing and its two-digit number, “Rule 01”, “Track 02”, “Stage 03”.
  • Button names: “Move {title} up”, “Move {title} down”, “Remove {title}”.

Code

<ft-repeat-list label="Rules">
  @for (rule of rules(); track rule; let i = $index, first = $first, last = $last) {
    <ft-repeat-row [heading]="'Rule ' + pad(i + 1)" [object]="rule.title" [first]="first" [last]="last"
      (moveUp)="move(i, -1)" (moveDown)="move(i, 1)" (remove)="remove(i)">
      … the row's ft-form-fields …
    </ft-repeat-row>
  }
</ft-repeat-list>
Input / outputEffect
ft-repeat-list labelAccessible name of the <ol> (required).
headingThe row’s heading, “Rule 01” (required).
objectThe row’s name in its button labels; the heading when empty.
first / lastDisable Move up / Move down.
moveUp, moveDown, removeAsk the caller to change its rows. Track rows by identity so a row’s focus follows it.
