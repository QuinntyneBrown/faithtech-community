Select

A select picks one value from a short, known list, like a partner’s stage or the role an invite joins with. It is always the native control, with a visible label.

Overview

A select lets someone pick one value from a short, known list: a partner’s stage, the role an invite joins with, an event’s city, a work item’s status. It is the native <select>, restyled only on the closed control; the open list is the browser’s own, so it is keyboard, screen reader and touch friendly for free. Added for FaithTech Community (not inherited from Shelfie).

  • Use it for 4 to roughly 15 options where the choice is not worth seeing all at once: city, role, assignee, story points, audit-log action.
  • Use a radio group for 2 or 3 options a person should compare, such as the stage choice in Move partner.
  • Use chips for filters that toggle independently (Upcoming, Past, Hackathons, Online on Events).
  • Use a search field when the list is long or open-ended (people, contacts). A select never holds every member.

Anatomy

  1. Label.field__label, a real <label for>; it is the accessible name.
  2. Control.select: --control-height-md tall, --radius-md, 1px --color-border-strong border, --color-bg-surface fill.
  3. ChevronTwo currentColor gradients in the right padding, so it follows the text colour in both themes. Not a separate element.

Variants

One visual style. The variants FaithTech uses differ in what surrounds the control, not in the control itself.

As a filter

Filter selects keep a visible label and start on an “All …” option (Events, Team, Audit log, Backlog). The list updates on change; there is no Apply button.

Sizes

The select has one height, --control-height-md, so it lines up with text fields on the same row. Width is set by its container: full width in forms and dialogs. In a filter row the field takes a width class instead: .field--sm (12rem, the events and team City filters), .field--md (14rem, the audit log Action filter) or .field--lg (16rem, the backlog and Kanban "Show stories from" filter). Each caps at 100% so it never overflows a phone. In Angular, <ft-form-field width="sm|md|lg"> applies the same widths.

  • Invalid sets aria-invalid="true" (danger border) and a .field__error linked with aria-describedby, as in Reassign owner and New work item. The error appears after a submit attempt, never on first render.
  • Busy: while a dialog submits, the mocks leave the select enabled; prefer disabling the whole form’s controls so nothing changes mid-save, matching the disabled Cancel button.
  • Hover darkens the border to --color-fg-muted, as on a text input. Disabled takes the subtle fill (--color-bg-subtle), the default border, --color-fg-disabled text and a not-allowed cursor, matching a disabled .input.

Responsive behaviour

  • In forms and dialogs the select is full width at every breakpoint.
  • In filter rows it keeps a fixed width beside chips and wraps onto its own line below --layout-breakpoint-md; the .cluster wrapper handles the wrap.
  • On phones the open list is the platform picker (wheel on iOS, sheet on Android), which is why we keep the native element.
  • Option text never truncates in the closed control at 360px; keep options under about 30 characters (“Grace Okonkwo (Toronto)”).

Theming

The select reads only semantic tokens. The chevron uses currentColor, so it flips with --color-fg-default in dark mode without a second image. The open list inherits color-scheme from the theme, so the browser draws a dark list in dark mode.

Accessibility

Role and pattern

Native <select>: role combobox (single-select, collapsed) is exposed by the browser. No ARIA is added except aria-invalid and aria-describedby.

Keyboard

KeyAction
TabMoves focus to the select.
Space / Alt+↓Opens the list.
↑ / ↓Changes the value (closed, on Windows) or moves through options (open).
Type a letterJumps to the next option starting with it (“C” for Confirmed).
Enter / EscChooses / closes without changing.

Labelling

Every select has a visible <label for>, including filters; a placeholder option (“Choose a City Lead”) is not a label. Help and error text are joined with aria-describedby.

Focus

:focus-visible draws the shared 2px --color-focus-ring with no offset, the same as text fields.

Touch

--control-height-md (40px) clears the 24px minimum; the platform picker takes over on touch.

Content

  • Labels are nouns in sentence case: “Stage”, “Home city”, “Join with role”, “Show stories from”.
  • Use the product’s exact terms for options: Lead, In funnel, Confirmed; City Lead, Staff, Volunteer, Product Engineer, Attendee.
  • A required select with no sensible default starts on an instruction option (“Choose a City Lead”) and errors if it is left there.
  • Filters start on “All cities” / “All actions”. Order options logically (pipeline order, Fibonacci points), else alphabetically.
  • Put the limit in the label when it matters: “New owner (City Leads only)”.
