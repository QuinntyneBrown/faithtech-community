Tag input

Free-text tags as removable chips inside one field. Typing suggests the tags already in use so spellings stay the same; Enter or a comma adds a new one.

WCAG 2.2 AAStatus: newft-tag-input

Overview

Use the tag input for free tags on a record: the Tags field of Add a resource and Edit a resource. Suggestions come from the feature ("Tags already in use", with how often each is used); the component only shows them. For a fixed set of choices use a checkbox group or filter chips; for people use the person picker, which shares this field's look.

Anatomy

  1. Label"Tags (optional)" from the form field.
  2. Chips.chip.chip--removable, each with a 44px remove button "Remove tag {tag}".
  3. Text input.tag-input__field: the combobox; grows to fill the rest of the line.
  4. Suggestions.combobox__panel with a listbox "Tags already in use": "{tag}" and "Used on {N} resources", then "Add “{text}” as a new tag".
  5. Help"Press Enter or comma to add. Pick an existing tag so spellings stay the same."

  • Tags are lower-cased, trimmed and de-duplicated as they are added; adding one that is already a chip does nothing.
  • Backspace in an empty input focuses the last chip's remove button; it never deletes silently.
  • Disabled: the whole field is disabled while the form submits.

Responsive behaviour

  • Chips wrap; the input keeps at least 8rem and drops to its own line when needed.
  • The suggestion panel is as wide as the field and never wider than the viewport.

Theming

The field reads --color-bg-surface and --color-border-strong, focus --color-focus-ring, invalid --color-danger-solid. Chips and the panel read the chip and combobox tokens.

Accessibility

Role and pattern

APG combobox with list autocomplete: the input has role="combobox", aria-autocomplete="list", aria-expanded, aria-controls and aria-activedescendant; the panel is a listbox named "Tags already in use". The chips are a list of buttons named "Remove tag {tag}". Adding or removing a tag is announced politely ("hackathon added").

Content
