QR presenter

One QR code filling the screen, for a projector or a phone held up to a room. A lead opens it from Share the hub with Show full screen; Esc or Close full screen returns to where they were.

WCAG 2.2 AAStatus: new

Overview

The presenter is a full-screen modal view around a QR code at the fill size. It shows a title (what the code opens), a one-line lead, an optional note, the code as large as the screen allows, the link as text, and a hint that Esc closes it. It is opened in a CDK dialog with DialogService.open(…, …, { fullScreen: true }), which fills the viewport, and it asks the browser for full screen too, so a projector shows nothing else. Leaving the browser’s full screen closes it, and closing it leaves the browser’s full screen.

Anatomy

  1. Close full screen: a secondary button at the end of the first row, focused when the view opens.
  2. Title: an h2 naming what the code opens (the event’s name); it labels the dialog.
  3. Lead: what to do, “Scan with a phone camera to open the hub”.
  4. Note (optional): a warning alert, such as a draft hub’s.
  5. Code: ft-qr-code at fill, with no caption (the lead says it).
  6. Link: the same link as text, large, wrapping anywhere so it never scrolls sideways.
  7. Hint: “Press Esc to close”.

Variants

Two: without a note (default) and with a note. The note sits between the lead and the code so it is read before anyone scans.

Sizes

One size: the whole viewport. The code takes min(50dvh, 80vw) (the QR code’s fill size), which leaves room for the title, link and hint on a 1280 × 720 projector without scrolling. The examples on this page are scaled down to fit.

States

One state, shown. Nothing loads or saves: the value is already known when the view opens. Close full screen has the button’s hover, active and focus-visible states.

Responsive behaviour

  • Projector and desktop (1280 × 720 and up): everything fits without scrolling; the title uses --text-display.
  • Tablet portrait: the code grows to 80% of the width, up to half the height.
  • Phone (360px): the title drops to --text-h1 and the link to --text-body; the view scrolls vertically when a note makes it taller than the screen (justify-content: safe center, so nothing is cut off at the top). Nothing scrolls sideways.

Theming

The view uses --color-bg-canvas and --color-fg-default; the code’s plate stays light in both themes, so in the dark theme it reads like a lit card on a dark screen.

Accessibility

  • The CDK container is role="dialog" with aria-modal="true", labelled by the title. Focus moves to Close full screen, is trapped inside, and returns to the button that opened it.
  • Esc closes it (2.1.2, no keyboard trap), and so does Close full screen. When the browser is in full screen, its own Esc leaves full screen and the view closes with it, so one Esc is always enough.
  • The code has alt text naming its destination, and the link is shown as text under it, so the code is never the only way (1.1.1).
  • Contrast: title, link and hint on the canvas meet 4.5:1 in both themes; modules on the plate are 21:1.
  • Nothing moves or flashes.

Content

  • Title: the name of what the code opens, as it appears elsewhere (“Toronto Builders Night”).
  • Lead: “Scan with a phone camera to open the hub”.
  • Button: “Close full screen”. Hint: “Press Esc to close”.
