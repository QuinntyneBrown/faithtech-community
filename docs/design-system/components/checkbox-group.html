Checkbox group

Any number of choices from a visible list: who joins a workspace, who to invite to Planning Poker, which stories go into a sprint. Native checkboxes in a fieldset, drawn with the .choice row and a square box.

WCAG 2.2 AAStatus: stableNative <input type="checkbox">

Overview

A checkbox group asks for none, one or several options that can all be seen at once. Each option is a label.choice around a native checkbox, and the group is a fieldset with a legend. It shares the row of the radio group, but the box is square with a tick, so a multi-select never looks single-select.

  • Use it for member pickers (create workspace, add members, start Planning Poker) and story pickers (start sprint, start Planning Poker).
  • Use a radio group when exactly one option must be chosen.
  • Use a switch for one on/off setting that applies at once.

Anatomy

  1. Legendlegend.field__label: names the list.
  2. Hint (optional)A .text-caption line saying who or what can be chosen.
  3. CheckboxA native checkbox drawn with appearance: none: a --size-icon-md square with --radius-xs, accent fill and an on-accent tick when checked.
  4. Label and description.choice__text in --text-body, with an optional small line (roles, points).

Variants

Stories to estimate
With descriptions (start poker "Stories to estimate", start sprint "Stories from the backlog").
Members

Everyone with a lead or volunteer role is already in this workspace.

Empty: the hint says why there is nothing to choose.

Tasks 1 of 2 done

Tasks
Checklist: a visible heading names the group, so the legend is visually hidden (legendHidden). Each change saves at once (a story's tasks on the work item page).

Sizes

Not applicable. One size at every width.

States

UncheckedCheckedHoverDisabledInvalid
  • Invalid: when the group needs at least one choice ("Choose at least one person.", "Choose at least one story to estimate."), the fieldset gets aria-invalid="true" and aria-describedby pointing at the inline message under the last option.
  • Disabled: the whole group is disabled while its dialog is busy.

Responsive behaviour

  • Options always stack vertically so names and descriptions wrap cleanly at 360px.
  • Long lists scroll inside the dialog body, never the page.

Theming

The same tokens as the radio group: --color-bg-surface and --color-border-strong unchecked, --color-accent and --color-fg-on-accent checked, --color-fg-disabled disabled and --color-danger-solid invalid, in both themes.

Accessibility

Role and pattern

Native checkboxes inside a <fieldset> with a <legend>. No ARIA roles.

Keyboard

KeyAction
Tab / Shift+TabMoves between checkboxes.
SpaceChecks or unchecks the focused option.

Labelling

The legend is announced on entering the group; each option's label and description are its name because the input sits inside the label.

Touch

Each row is at least --target-min tall and the whole label is the target.

Content

  • The legend is a short noun: "Members", "Stories to estimate", "Stories from the backlog".
  • Descriptions carry the deciding detail: a person's roles, a story's points.
  • The error asks for the smallest valid choice: "Choose at least one person."

Do and don't

Tokens

As the radio group, plus --radius-xs for the box corners and --border-width-thick for the tick.

Code

<fieldset class="stack">
  <legend class="field__label">Members</legend>
  <p class="text-caption">Only people with a lead or volunteer role can be added.</p>
  <label class="choice"><input type="checkbox" checked>
    <span class="choice__text">Marcus Lee<small>Event Lead</small></span>
  </label>
</fieldset>

In Angular: <ft-checkbox-group legend="Members" hint="…" [formControl]="ids"><ft-checkbox value="…" description="Event Lead">Marcus Lee</ft-checkbox></ft-checkbox-group>. The control's value is the array of checked values.
