Tabs

Tabs switch between sibling views of one thing, like a workspace’s Board, Backlog, Planning Poker and Settings. In FaithTech they are almost always links to separate pages.

Overview

Tabs switch between sibling views of one thing: a workspace’s Board, Backlog, Planning Poker and Settings, or the System Admin area’s Users and Audit log. The same .tabs / .tab styles serve two different patterns, and choosing the right one is the main decision. Added for FaithTech Community.

  • Navigation tabs (<nav> of links with aria-current="page"): each tab is its own URL. This is the only pattern the mocks use, and the default for every new screen.
  • APG tabs (role="tablist" of buttons with aria-selected): panels swap in place without changing the URL. Use only for a small in-page switch whose panels are not worth a route.
  • Use the tab bar for the phone-wide primary navigation, and chips for filters.

Anatomy

  1. Tab list.tabs: a flex row with a 1px --color-border-default baseline and --space-4 below; scrolls horizontally when it overflows.
  2. Tab.tab: --text-label, --color-fg-muted, --target-comfortable tall, --space-3 side padding.
  3. Current indicatorA --space-0-5 bottom border in --color-accent and --color-fg-accent text, set by aria-current or aria-selected.

Sizes

Tabs have one size, --target-comfortable tall with --text-label. Do not shrink them in dense headers; there is never more than one tab row per page.

Hover and focus are forced here with data-state="hover" and the global data-state="focus"; in use they come from :hover and :focus-visible.

  • Exactly one tab is current. A page reached outside the tab set (for example a work item) shows no tab row rather than a row with nothing current.
  • Forbidden: tabs the person cannot open are removed, not disabled. A Staff member sees Board and Backlog read-only; a disabled tab would hide its reason.
  • Loading and error states belong to the panel below the tabs; the tab row stays usable so people can leave a failing view.

Responsive behaviour

  • The row scrolls horizontally (scrollbar hidden) when tabs overflow at 360px; it never wraps to two lines.
  • Keep labels short (one or two words) so four workspace tabs fit at 360px without scrolling.
  • The current tab should be scrolled into view on load if the row overflows.

Theming

Tabs read --color-fg-muted, --color-fg-default (hover), --color-fg-accent and --color-accent (current) and --color-border-default. The violet accent inherited from the Shelfie tokens lightens in dark mode so the current label stays above 4.5:1 on the page.

Accessibility

Role and pattern

Navigation tabs are a <nav aria-label> landmark of links; the current link has aria-current="page". No tab roles. APG tabs follow the WAI-ARIA Tabs pattern: role="tablist" with a label, role="tab" buttons with aria-selected and aria-controls, and role="tabpanel" panels labelled by their tab. Never mix the two: links with role="tab" confuse both models.

Keyboard

KeyAction
Tab (navigation)Moves through every tab link in order; Enter follows it.
Tab (APG)Enters the tab list on the selected tab, then moves to the panel.
← / → (APG)Moves to and selects the previous / next tab, wrapping.
Home / End (APG)First / last tab.

Focus

The global focus ring (2px --color-focus-ring, 2px offset) draws around the tab; it does not replace the current indicator.

Labelling

The nav or tablist has an aria-label (“Workspace sections”, “Admin sections”). Count badges inside a tab are part of its name; keep them short.

Touch

Each tab is --target-comfortable (44px) tall with 4px between tabs.

Content

  • Tab labels are nouns in title or sentence case as the mocks use them: Board, Backlog, Planning Poker, Settings; Users, Audit log.
  • Every tab in a set leads to a page that shows the same tab row with that tab current. A destination outside the set (People, where roles are assigned) is a top-bar link, never a tab.
  • One or two words. No verbs, no icons without text.
  • Keep the same order on every page of the set so the current tab does not jump.

Drift noticed in those mocks:

  • Resolved: the tab rows no longer carry an inline margin-bottom; .tabs owns the --space-4 gap below it (and ft-tabs in Angular).
  • Resolved: the APG (aria-selected) pattern is documented as reserved, since no v1 mock needs in-page panels. The CSS selected style now requires role="tab", so it cannot be put on links; in Angular, ft-tabs renders APG tabs only when no ft-tab has an href, and links only ever get aria-current.
  • Resolved: .tab:hover, .tab[data-state="hover"] share one rule in components.css, so the states matrix shows hover.
  • Resolved: the Admin “Roles” tab linked to people/admin, a page without the same tab row. It is removed; the Admin tabs are Users and Audit log, and roles are assigned from People (top bar), which already serves System Admin (pages/people/admin).
