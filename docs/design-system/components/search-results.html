Search results

Search results group what FaithTech search found — people, events, partners, work items and your own private contacts — and highlight why each one matched.

Overview

Search results show what global search found, grouped by type: People, Events, Partners, Work items in your workspaces and Your private contacts. Each group is a search group — an overline heading with the count, above a flush list. The matched words are wrapped in <mark>.

  • Use it only on pages/search. Rows reuse list items and the event card; the group is what this component adds.
  • The server decides which groups a person gets. A member sees People and Events; Grace, a City Lead, also sees her workspaces' items and her own private contacts. Never send a group and hide it in the UI.
  • Groups with no hits are left out, not shown empty. When every group is empty, show the no-results empty state.

Anatomy

  1. Group title.search-group__title: an <h2> styled as an overline, type and count, labels the section.
  2. Result rowA .list__item (or .event-card) in a flush card: avatar or badge, title link, meta, optional badge.
  3. Highlight<mark> around the matched term, --color-warning-bg with inherited text colour.

Variants

The groups, in their fixed order. Rows keep the look of their own type.

Responsive behaviour

  • Groups stack in one column at every width, separated by --space-6.
  • Rows wrap: meta lines and badges drop below the title on a phone; nothing truncates, so the highlighted word is never cut off.
  • The search form above is a wrapping cluster; the field is .input--grow, so it fills the row and wraps below 12rem.

Theming

The group title reads --color-fg-muted. <mark> is --color-warning-bg with inherited colour, so it stays readable on muted and default text in both themes. Rows inherit their own component tokens.

Accessibility

Role and pattern

Each group is a <section aria-labelledby> with an <h2>, so screen reader users can jump between groups by heading or landmark. The result count is a role="status" paragraph, announced after each search.

Keyboard

KeyAction
TabFrom the search field to the button, then through each result title in group order.
EnterIn the field, runs the search; on a title, opens the result.

Labelling

<mark> is not announced by most screen readers, which is fine: the match is in the text. Never use the highlight to carry meaning the text lacks. The Private badge says "Private" in words.

Content

  • Group titles name the type and the count: "People (1)", "Events (1)". Scope groups say whose they are: "Work items in your workspaces", "Your private contacts".
  • The status line repeats the query in curly quotes: "5 results for “shelter”".
  • Meta shows why it matched when the match is not in the title: "Note: runs IT at Harbour Light Shelter".
  • No results: "No results for “zebra crossing”" then one helpful suggestion.

Spacing comes from classes: .search-form puts the form 16px above the results, .stack.search-results puts the groups 24px apart, and the query input is .input--grow. The work-item row leads with .icon-tile.icon-tile--sm (in Angular, the result's icon), not an estimate card. While searching, the skeleton mirrors the groups: round avatars for people and partners, the square .skeleton--date-badge for events.
