Component · Status

Badge

A small, non-interactive pill that labels something in one or two words: a member's role ("City Lead"), a work item's type ("Story"), a status ("Public", "Cancelled", "Suspended"), or how many notifications are unread.

Overview

Use a badge to tag a row, card or heading so a lead can scan a list. A badge is never clickable: a filter you can press is a chip, and anything that needs a sentence is an alert or inline message.

  • Status (uppercase, with dot): the state of an event, invite, photo or account. Neutral, info, success, warning and danger tints.
  • Role (badge--role, sentence case, no dot): a person's global roles on profiles, Team and People, and the work-item type on boards and the backlog.
  • Count (badge--count): unread notifications on the bell.
  • Tally (neutral status badge holding a number): items in a Kanban column, "4 of 10" photos.

Anatomy

  1. Dot8px circle in currentColor, drawn by ::before. A second cue besides the tint; hidden on role and count badges.
  2. Label--text-overline (small, uppercase, wide tracking) for status; --text-label in sentence case for roles.
  3. Pill--radius-full, 24px tall (--target-min), 8px side padding, status tint.

Variants

Status

Pick the tint by meaning: neutral for plain facts, info for an open or visible state, success for done or chosen, warning for in between or lapsed, danger for stopped.

Sizes

One size: 24px tall. A count badge is at least 24px wide so a single digit makes a circle.

States

Badges are not interactive, so there is no hover, focus, active or disabled state. When the status changes the badge is replaced: an invite's "Pending" becomes "Accepted" or "Expired"; an event becomes "Cancelled". When the unread count reaches zero the count badge is removed, never shown as "0".

Responsive behaviour

  • Badges never wrap (white-space: nowrap) and never truncate; keep labels to one to three words.
  • Several role badges sit in a .cluster and wrap as a group; Samuel's "Create Lead" and "Product Engineer" take two lines on a 360px profile header.
  • In a list row the badge sits at the end and the title wraps first: "Austin Faith & AI Panel" wraps, "Cancelled" stays whole.

Theming

Each variant reads a status pair: --color-{info,success,warning,danger}-bg for the tint and --color-{status}-fg for the label and dot. Neutral and plain role use --color-bg-subtle and --color-fg-muted. Count uses --color-danger-solid with --color-fg-on-danger. In dark mode the tints darken and labels lighten, keeping every pair above 4.5:1.

Accessibility

Role and pattern

A plain <span> with text and no ARIA role: the status is read as part of the row, for example "Victor Kane, victor@example.org, Suspended".

Keyboard and focus

Never focusable. Inside a link (the bell) it is part of that link's target.

Labelling

The visible word is the label; colour and dot are extra cues (1.4.1). Role colours on work-item types are never the only cue, because the type is written out. The count badge is aria-hidden="true" and the bell link carries the full name, "Notifications, 3 unread", so the number is not read twice. Status text is uppercase by CSS only; write it in sentence case in the HTML.

Motion

None. A count that changes does not pulse.

Touch

Not a target on its own.

Content

  • One to three words, sentence case in the source: "Members only", "In funnel", "Signed up".
  • Role names are exactly the role: "City Lead", "Product Engineer". Never abbreviate ("PE") or pluralise.
  • List roles in the order they were granted; no role is highlighted.
  • Counts above 99 read "99+".
