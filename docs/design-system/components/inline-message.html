Inline message

One line of text right under the thing it is about. A field error tells a member how to fix one answer, such as an event title, a photo description or the DELETE confirmation, without leaving the form.

WCAG 2.2 AAStatus: stablearia-describedby / role="status"

Overview

  • Field error (.field__error): under one input, select or textarea, after a submit finds a problem with it. Pair it with a form summary when a page form has more than one field.
  • Group error: the same .field__error as the last child of a fieldset of radios or checkboxes ("Choose a role to add."), linked from the fieldset.

Do not use it for news that is not about the element above it; that is an alert or a toast. Saving progress is shown on the submit button ("Saving…", see button), not as an inline message. Shelfie’s inline status (.inline-status) is still in the stylesheet but no FaithTech mock uses it, so it is not documented here.

Anatomy

  1. Error glyph⚠ from .field__error::before; the text, not the glyph, carries the message.
  2. Error textSmall body text in --color-danger-fg, linked to the field with aria-describedby.
  3. Invalid controlaria-invalid="true" turns the border --color-danger-solid.

Small body text (--text-body-sm) at every size of field, including the small photo-description inputs.

  • A field error appears after submit, never while typing; it clears once the field is valid on the next submit.
  • In a dialog the error sits under its field and the dialog stays open; there is no form summary in dialogs.

Responsive behaviour

  • Field errors wrap under the field at every width; the glyph stays on the first line.
  • In a two-column form row (start and end time) each error stays under its own field and the row stacks below 640px.

Theming

Field errors read --color-danger-fg and invalid borders --color-danger-solid. Both are tuned per theme to stay above 4.5:1 (text) and 3:1 (border) on cards, the page and dialogs.

Accessibility

Role and pattern

A field error is plain text tied to its control with aria-describedby, with aria-invalid="true" on the control (WCAG 3.3.1, 3.3.3). For a radio or checkbox group, put aria-describedby on the fieldset.

Keyboard

KeyAction
TabMessages are not stops. Focusing an invalid field reads its label, then its error.

Focus

On a failed submit focus moves to the form summary, or to the first invalid field in a dialog or a one-field form.

Labelling

Put the error id first in aria-describedby, before the help text, so the problem is read first. The ⚠ comes from CSS content and some screen readers read it as "warning sign"; the sentence still makes sense with it.

Content

  • Say how to fix it, not what is wrong in the abstract: "Enter an email like name@example.org.", "Use at least 12 characters."
  • Give the reason when it helps: "Describe what’s in the photo for people using screen readers.", "Give a reason so other admins understand."
  • Groups start with a verb: "Choose a role to add.", "Choose at least one person."
  • Sign-in errors never say which of the two fields was wrong: "Email or password is wrong. Check both and try again."
