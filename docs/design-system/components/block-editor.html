Block editor

The surface of a Notes page: the page title, an optional emoji icon and an ordered list of blocks the owner writes, formats, inserts and reorders in place. Readers get the same blocks as plain content.

Overview

The block editor is a content editor, not a form (ADR 0024): each text block is its own contenteditable region, a handle on every block opens the block menu and is the drag grip, and changes are saved by autosave (save status), never by a submit button. It is built once in components with no third-party editor; Angular CDK drag-drop reorders blocks and CDK Overlay positions the block menu, the slash menu and the formatting toolbar.

  • Use it for the body of a Notes page (/notes/{id}), in the editor for the owner and a System Admin, and in the read-only rendering for everyone else who may open the page.
  • Do not use it for short structured input such as a description or a note on a contact; use a textarea in a dialog. Every form the Notes feature needs (share, page settings, move, add image, add link) stays a dialog.
  • The page's actions (visibility badge, save status, Share, More actions), banners and the Pages inside and Linked from sections sit around the editor and are composed by the notes library.

Anatomy

  1. Icon.block-editor__icon: the page's emoji, 64px, a button that opens Page settings ("Change the icon, now 🛠️"). With no icon nothing is shown; the owner adds one from Page settings in "More actions".
  2. Page title (ft-page-title).block-editor__title: a single-line text box labelled "Page title" with the placeholder "Untitled", inside the page's only <h1>. At most 200 characters; Enter moves to the first block; paste is plain text on one line.
  3. Meta line.block-editor__meta: owner, parent and the edited time, --text-body-sm muted.
  4. Drag handle.block__handle: a 24px button (32px on touch) with the grip icon, labelled "Move or open the menu for block {n} of {total}, {type}". Hidden until the row is hovered or focused; always shown on touch screens.
  5. Block row.block.block--{type}: a two-column grid, handle then content. The block list is .block-editor__blocks, a group named "Page content".
  6. Block content.block__text: the editable region, a multi-line text box named by its type ("To-do", "Heading 2"). Other types put their own parts here (checkbox, callout icon, image, link card).
  7. Page link.page-link: an inline chip with the target's icon and current title, or the muted "Private page" chip.

Two parts appear only while something happens: the block menu (.menu.block__menu, opened from a handle) and the drop indicator (.drop-indicator, during a drag). The polite live region .block-editor__live is always in the DOM and visually hidden.

Thirteen types, in slash-menu order (wire names in brackets, BLOCK_TYPES in the library). Every type except Divider, Image and Link card holds rich-text spans. Editor and read-only

The same blocks render two ways. canEdit from the API decides: the owner and a System Admin get the editor; every other reader gets the read-only rendering (.block-editor--readonly): no handles, no contenteditable, no slash menu, toolbar or move shortcuts, and the grid drops its handle column. Text blocks become <p>, headings stay headings and hyperlinks stay links.

Block menu

The handle opens the block menu, a menu anchored under the handle. It offers Turn into (a submenu of the text-bearing types), Move up, Move down, Duplicate and Delete; a Callout adds Change icon and an Image adds Edit alt text. Move up is disabled on the first block and Move down on the last.

A Callout's menu with Turn into focused, and the first block's menu (an Image) with Move up disabled. From pages/note/block-menu. Turn into is not offered for Divider, Image or Link card.

Dragging

Mid-drag the source row stays as a faded dashed placeholder (.block--dragging), a raised preview follows the pointer (.block--preview, --shadow-3, tilted 1°) and a 2px accent line with a ring at its start marks the drop position (.drop-indicator). Escape or dropping outside the page cancels.

Moved by keyboard

Alt+Shift+↑ / ↓ (or Move up / Move down) moves the focused block one place, keeps focus and the caret, washes the row with --color-accent-subtle plus the focus ring for --duration-slow (.block--moved) and announces the move in the polite live region.

Paused, conflict and empty

  • Paused (.block-editor--disabled): after a 409 conflict or a 403, editing stops. Text boxes get contenteditable="false" with aria-readonly="true", handles are disabled and the surface dims to 60%; text can still be selected and copied. The banner above it says why ("This page changed somewhere else" with Reload page). See Autosave and edit conflicts.
  • Empty page: one empty Text block whose placeholder reads "Type / for blocks, or [[ to link a page" ([data-placeholder]:empty::before, --color-fg-subtle).
  • Full: at 500 blocks no block is added and the page shows "A page holds up to 500 blocks. Start a new page inside this one."
  • Selected (.block[data-state="selected"]): the accent-subtle wash used while a block is the target of its open menu.
  • Loading and error belong to the page: a skeleton region named "Loading page", or the error empty state "We couldn’t load this page".

Responsive behaviour

  • One column at every width; the editor is centred at --layout-measure and shrinks with the container below it, keeping the 16px page gutter at 360px.
  • On touch screens (@media (hover: none)) handles are always visible and 32px; on a pointer they show on hover and focus.
  • Nothing scrolls horizontally except a long line in a Code block, which scrolls inside .code-block. Images, link cards (the URL ellipsises) and page links (overflow-wrap: anywhere) never widen the page.
  • Below 640px the block menu and slash menu span the editor's width; the formatting toolbar stays inside the viewport (L2-099 AC11).
  • At XS the page's actions collapse into "More actions"; that is page composition, not part of the editor.

Theming

Everything reads role tokens: text --color-fg-default, quote and meta --color-fg-muted, placeholders and the handle icon --color-fg-subtle, callouts --color-bg-subtle, code --color-bg-surface-sunken, page links --color-accent-subtle with --color-fg-accent, the drop indicator --color-accent. In dark the sunken code well and subtle callout read against the dark page without a shadow; the drag preview uses --color-bg-surface-raised, lighter than the page. Under forced-colors callouts, code, link cards and page links get a CanvasText border and the drop indicator uses Highlight.

Accessibility

Role and pattern

The block list is role="group" named "Page content" (L2-099 AC2). Each editable block is role="textbox" with aria-multiline="true", named by its type ("Text", "Heading 2", "To-do"); the title is a single-line textbox named "Page title". Each handle is a native <button> following the APG Menu Button pattern (aria-haspopup="menu", aria-expanded) and the block menu is a CDK Menu. The slash menu and page-link suggestions are combobox listboxes (slash menu); the formatting toolbar is an APG Toolbar (formatting toolbar).

Dragging Movements (WCAG 2.5.7)

Every drag has a single-pointer alternative: the handle is clickable, and Move up / Move down in the block menu reach every position one click at a time; Alt+Shift+↑ / ↓ is the keyboard path. The drop indicator is never the only feedback: the move is announced.

Focus

Focus is never lost to the top of the page: after insert, split, delete, duplicate, Turn into or a move, it lands as the keyboard table says (L2-099 AC5). A focused text box shows the 2px focus ring flush with its box; a handle shows the ring around the button. Focus Not Obscured (2.4.11): the editor scrolls the caret's block into view with scroll-margin clearing the sticky top bar, the phone tab bar, a banner and the formatting toolbar, so the focused block is never hidden behind them.

Labelling and announcements

Handles are labelled "Move or open the menu for block {n} of {total}, {type}" (L2-089 AC1), updated as blocks move. A To-do's checkbox is named by its text. Callout emoji, page-link icons and the handle grip are aria-hidden. Hyperlinks to https:// end with a visually hidden "(opens in a new tab)". The live region .block-editor__live (role="status", polite) carries move announcements; the save status carries its own.

Motion

Handles fade in over --duration-fast; a keyboard move flashes the row over --duration-slow. Under prefers-reduced-motion the move wash does not animate and CDK drag-drop's sort animation is turned off, so blocks jump into place (L2-099 AC12).

Touch

Handles are 32px and always visible on touch; To-do checkboxes sit in a 24px-minimum target; block menu items are 36px. Long-press on a handle starts a drag; a tap opens the menu.

Content

  • Empty title shows as "Untitled" everywhere the page is named; never "New page" or "Untitled page".
  • The empty-block hint is exactly "Type / for blocks, or [[ to link a page".
  • Block type names are the ones the slash menu uses: Text, Heading 1, Heading 2, Heading 3, Bulleted list, Numbered list, To-do, Quote, Callout, Code, Divider, Image, Link card.
  • Move announcements: "Moved {type} “{first words}” to position {n} of {total}", for example "Moved Heading 2 “Run sheet” to position 3 of 12".
  • A page link to a page the viewer can't open reads "Private page", never the title or "Hidden".
  • Image alt text describes the image ("Two builders pairing at a whiteboard…"), not "Image of…" and never the file name.

  [blocks]="editorBlocks()"                 <!-- readonly EditorBlock[]; the editor edits a copy -->
  [readonly]="!editable() || !!stop()"      <!-- read view: h2-h4, real ul/ol, blockquote, no handles -->
  [pageLink]="pageLink"                     <!-- PageLinkResolver: span -> { text, icon, href } or "Private page" -->
  [pageSearch]="pageSearch"                 <!-- (q) => Promise<PageLinkItem[]>, for "[[" -->
  [imageSrc]="imageSrc"                     <!-- (imageId) => Promise<url>, fetched with the member's token -->
  (blocksChange)="onBlocks($event)"         <!-- EditorBlock[] on every change; the page autosaves -->
  (refused)="refused($event)"               <!-- e.g. "A page holds up to 500 blocks. Start a new page inside this one." -->
  (blockRequested)="request($event)"        <!-- { type: 'link' | 'image', index, replace }: open the dialog -->
  (linkRequested)="link($event)"            <!-- { index, start, end, href }: open Add a link / Edit link -->
  (blockEditRequested)="editBlock($event)"  <!-- { index, block }: Change icon (callout) or Edit alt text (image) -->
/>

// Methods the page calls back with: focusFirst(), place(request, block),
// update(index, block), applyLink(request, href | null)

The library owns the editing model (EditorBlock, EditorSpan, BLOCK_TYPES and the span helpers in block-editor/editor-model.ts) and knows no API. The notes library maps the page in, answers the editor's requests for a dialog (Add an image, Add a link card, Add a link, Edit alt text, Change icon) and for page-link suggestions, and runs autosave. The component's own API docs are the reference for the exact types.
