Top bar

The bar across the top of every signed-in page: the FaithTech brand, the primary nav, global search, the notification bell and the profile avatar. Grace sees all eight sections; Staff never see Contacts.

WCAG 2.2 AAStatus: stableNative <header> + <nav> + role="search"

Overview

Every signed-in page starts with a .topbar. It keeps the way home, search, notifications and your own profile one tap away, and it stays put while the page scrolls. Sign-in, sign-up, verify email, forgot and reset password and accept invite have no top bar; they use the auth layout. The public event page shows a reduced bar for anonymous visitors.

  • Member: brand (back to Home), .topbar__nav with Home, Events, Contacts, Partners, Workspaces and the secondary links Team, Announcements, People; then .topbar__search, the .bell-anchor and the .avatar-trigger.
  • By role: the links follow one rule (ADR 0009, see the tab bar). Staff have no Contacts, because private contacts are visible only to the lead who created them and to System Admin; only System Admins have Admin; a member with no role sees Home, Events, Team and Announcements.
  • Anonymous (public event): brand and a "Sign in" button only.
  • The avatar opens the account menu (button.avatar-trigger): Your profile, Settings and Sign out. It is the one way to sign out of this device.

Anatomy

  1. Brand.topbar__brand: mark and "FaithTech" in --text-h4; links to Home.
  2. Navnav.topbar__nav of .nav-links; the current page has aria-current="page". .nav-link--secondary (Team, Announcements, People) hides between 768px and 1023px. The whole nav hides below 768px.
  3. Searchform.topbar__search[role=search] with a visually hidden label and an .input--sm; --layout-topbar-search-width (14rem) wide, shown from 1024px.
  4. Bell.bell-anchor holds a ghost icon button with a .badge--count; the anchor positions the .bell-panel when it opens.
  5. Avatarbutton.avatar-trigger wrapping a small .avatar with initials; opens the account menu.
  6. Capsuleheader.topbar: a pill (--radius-full) floating --space-2 below the top, container-wide, translucent blurred surface, hairline border and --shadow-2. Inherited from Shelfie unchanged.

Sizes

The bar is always --layout-topbar-height (56px) tall; only its contents change with width.

States

The bar has no state of its own; its parts do. Hover and focus are forced with data-state; current uses the real aria-current="page".

Both themes

FaithTech
FaithTech
  • Current nav link: --color-accent-subtle fill and --color-fg-accent text, plus aria-current="page".
  • Bell open: aria-expanded="true" and aria-controls naming the .bell-panel while it shows below it (see notifications/bell/unread).
  • Count badge disappears when nothing is unread; it never shows "0". The bell's name drops the count too.

Responsive behaviour

  • Base (phones): brand, spacer, bell, avatar. The tab bar carries Home, Events, Search, Contacts and Partners.
  • 768px to 1023px: .topbar__nav appears with the five primary links; .nav-link--secondary (Team, Announcements, People) stays hidden so the row never wraps. The tab bar hides.
  • 1024px and up: the secondary links and .topbar__search (--layout-topbar-search-width, 14rem) appear. Nav links never wrap (white-space: nowrap).
  • The capsule is position: sticky; top: var(--space-2) at --z-sticky; scroll-padding-top on html keeps focused fields clear of it.

Theming

The bar is --color-bg-surface at 90% over a backdrop blur, with a hairline --color-border-default and --shadow-2. Nav links read --color-fg-muted, --color-bg-subtle and the violet accent pair; the bell badge reads the danger pair; avatars read the avatar palette with --color-fg-on-cover. The dark theme changes only those semantic tokens.

Accessibility

Role and pattern

A native <header> (banner landmark) holding <nav aria-label="Primary"> of links and a <form role="search"> (search landmark). Current page is aria-current="page". The bell is a <button aria-haspopup="dialog"> that toggles the bell panel (aria-expanded, plus aria-controls while open); the panel, which links to the full Notifications page, is role="dialog" labelled "Notifications".

Keyboard

KeyAction
Tab / Shift+TabSkip link, brand, nav links, search, bell, avatar, then the page.
EnterFollows the brand, a nav link or the avatar; in search, submits to the Search page.

Esc in the panelCloses it and returns focus to the bell.

Focus

The shared 2px --color-focus-ring with 2px offset on every link, the search input, the bell and the avatar. scroll-padding-top reserves the bar's height (WCAG 2.4.11).

Labelling

The search input has a visually hidden label, "Search FaithTech"; the placeholder is a hint, not the label. The bell's name includes the count ("Notifications, 3 unread") and the visible badge is aria-hidden. The avatar is a menu button that says whose account it is: "Account menu for Grace Okonkwo". The brand mark is aria-hidden; "FaithTech" names the link.

Motion

Nav links fade their background over --duration-fast. The bar does not hide on scroll. Reduced motion zeroes the fade.

Touch

Nav links and the bell are --target-comfortable (44px). The avatar is 32px (--size-avatar-sm), above the 24px minimum, with space around it.

Content

  • The brand is always "FaithTech"; no page titles in the bar (the page header has the <h1>).
  • Nav labels are one word each, always in this order: Home, Events, Contacts, Partners, Workspaces, Team, Announcements, People. A link the person may not use is left out, not disabled.
  • Search placeholder: "Search people, events, partners".
  • Avatars show initials ("GO" for Grace Okonkwo); never a photo in the bar.

Drift noticed:

  • Resolved: .topbar__search was sized with a raw 14rem; it now reads --layout-topbar-search-width. Media queries cannot read custom properties, so the top bar's 48rem/64rem queries are the values of --layout-breakpoint-md/-lg (the rule is stated at the top of components.css), and the Angular TopBarComponent reads them by name with @include bp.up(md) from styles/_breakpoints.scss.
  • The top bar markup is copied by hand into every page mock (eight personas); a shared shell component is needed in the app.
