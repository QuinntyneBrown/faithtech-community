Text field

One line of text: an email, a venue address, a start time, a search. With an input group it carries one icon button: show password or copy link.

Overview

A text field takes one line of text: a name, an email, a venue address, a date and time, a capacity, a search. It is an input.input inside a form field. For several lines, use a textarea.

  • Plain: the native input with the right type (email, password, tel, url, number, datetime-local, search) and autocomplete, so phones show the right keyboard and browsers fill it.
  • Input group (.input-group): the input with one icon button inside its right edge (.input-group__btn). FaithTech uses it twice: show or hide password on sign in and sign up, and copy the shareable link of a public event.

Anatomy

  1. LabelFrom the form field; always visible.
  2. Input--control-height-md, --radius-md, hairline --field-border on --field-bg.
  3. Trailing button (input group only)A small ghost icon button inset by --space-1; the input gets right padding so text never runs under it.

Input group: show password and copy link

The eye toggles the input between password and text and sets aria-pressed; when pressed the eye is crossed out and turns accent, and the label stays "Show password" (sign-in/invalid shows it pressed). The copy button sits in a read-only URL field on the lead's event page and confirms with a success toast, "Link copied" (pages/event/link-copied).

Sizes

Medium is the default for forms. Small (.input--sm) is for the top bar search and compact rows: photo alt text on Edit profile, "Add a task" on a work item. Large (.input--lg) is the search box on the Search page.

Small 36px, medium 44px, large 52px. Both search inputs have a visually hidden label.

Both themes

  • Invalid (aria-invalid="true") thickens the border in --color-danger-solid; the message comes from the form field.
  • Read-only uses the sunken background: the invite email on Accept invite and the share link on the event page.
  • Disabled is not used in the mocks; while a page form submits its fields stay editable and only the buttons lock. In a busy dialog the field becomes readonly, not disabled, so its value stays readable.

Responsive behaviour

  • Inputs fill their container; the form sets the maximum width.
  • Text is at least 16px (--font-size-md) so iOS does not zoom on focus; the small size is used only where zoom is acceptable (top bar search).
  • The search page input (.input--grow) grows to fill its row and wraps below the filters under 12rem.

Theming

Two component tokens carry every state: --field-bg (default --color-bg-surface, read-only --color-bg-surface-sunken, disabled --color-bg-subtle) and --field-border (default --color-border-strong, hover --color-fg-muted, focus --color-focus-ring, invalid --color-danger-solid). The textarea shares both.

/* Each state only reassigns the two tokens */
.input:read-only:not(:disabled) { --field-bg: var(--color-bg-surface-sunken); }
.input[aria-invalid="true"] { --field-border: var(--color-danger-solid); }

Accessibility

Role and pattern

Native <input> with a <label for>. Use the right type and autocomplete (email, current-password, new-password) so password managers and autofill work (WCAG 1.3.5).

Keyboard

KeyAction
TabMoves into the input, then to its trailing button.
EnterSubmits the form.
Esc in a search inputClears the query (native).

Trailing button

"Show password" is a toggle: the label stays the same and aria-pressed says whether it is on. Switching the type does not move focus or the caret. "Copy link" announces its result through the toast's live region.

Focus

The shared ring with no offset, and the border takes the ring colour, so focus is visible on any background.

Labelling

Every input has a label. Search inputs whose purpose is obvious from the page use a .visually-hidden label, never just a placeholder. Placeholders are examples, not instructions.

Motion

Border colour fades over --duration-fast; reduced motion makes it instant.

Touch

Medium is 44px tall. The trailing button is 36px and inset, inside the 44px input.

Content

  • Prefill what you know: the signed-in email, the invite email, the event's current values when editing.
  • Placeholders give an example of the format, only where it helps: "Search people, events, partners".
  • Do not limit length silently; say the limit in help ("Up to 400 characters.").
  • Never prefill a password. In a mock, a password field that shows typed input holds a realistic value (value="harbour-26") that the browser masks; never type bullet characters into value.
