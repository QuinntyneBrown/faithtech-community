Event card

An event card lists one gathering — a Builders Night, a prayer and planning evening, a hackathon — so people can scan the date, see who can come and open it.

Overview

An event card is one row in a list of events: a calendar-leaf date badge, the event title as a link to its page, one line of when, where and how many are going, and a visibility badge. It appears on the Events page, the "Coming up" card on Home, and the Events group of global search.

  • Use it wherever several events are listed and people choose one to open.
  • Do not use it on the event page itself (pages/event, pages/public-event): there the date is the page subtitle and the event is the page. Those screens use the page header and an alert when cancelled.
  • Hackathons are an event type, so they use the same card. Hackathon teams, projects and judging are v2 and not part of it.

Anatomy

  1. Date badge.date-badge: month overline above the day number on an --color-accent-subtle leaf, 48px square. Decorative (aria-hidden); the date is repeated in the meta line.
  2. Title link.event-card__title: --text-h4, default foreground, underline on hover. The only focus stop in the row.
  3. Meta line.event-card__meta: weekday, date, time, place and attendance, separated by " · ".
  4. Visibility badgeBadge: Public (info), Members only (neutral) or Cancelled (danger).
  5. Row.list__item.event-card inside a flush card list; a flex row that wraps on narrow widths.

Two variants, decided by the event's status, and three visibility badges.

One size. The badge is fixed at --size-avatar-lg (48px) so every title lines up; the body takes the rest of the row.

  • Empty (pages/events/empty): "No events yet" with a New event action for leads.
  • Error (pages/events/error): the list is replaced by an error empty state with Try again.
  • Cancelled is a content state, not a disabled one: the title stays a working link to the cancelled event page, which explains why.

Responsive behaviour

  • The row is a wrapping flex row: on a phone the visibility badge drops under the body instead of squeezing the title.
  • The body has min-width: 0 and flex: 1 1 12rem, so long titles wrap rather than overflow; they never truncate.
  • The date badge never shrinks (flex: none).
  • The row itself is not a link; the title is the target, so nested links (badge, meta) stay possible later without conflicts.

Theming

The card reads semantic tokens only. The leaf is --color-accent-subtle with --color-fg-accent text, so a brand change to the accent recolours every date badge. Cancelled swaps to --color-bg-subtle and --color-fg-muted. In the dark theme the leaf darkens and the accent text lightens; contrast is checked below.

Accessibility

Role and pattern

A <ul> of <li> rows with a native <a href> title. The list sits in a section with a heading ("Coming up", or the search group title), so it is announced with its count.

Keyboard

KeyAction
Tab / Shift+TabMoves between event titles, one stop per event.
EnterOpens the event page.

Focus

The shared ring wraps the title link on :focus-visible.

Labelling

The date badge is aria-hidden because "Nov 6" read before the title is noise; the meta line carries the full date. Cancelled is said in words by the badge and the meta line, never only by the strikethrough or the muted colour (WCAG 1.4.1).

Motion

None. Hover only adds the underline.

Touch

The title's line box is well over the 24px minimum (WCAG 2.5.8) and rows are separated by the list dividers.

Content

  • Title is the event name as published: "Toronto Builders Night", "Hackathon: Tech for Shelters". No dates or city prefixes in the title.
  • Meta order: date, time, place, attendance — "Thu 6 Nov · 6:30 pm · Kestrel Labs, 220 King St W · 34 going". Dates use the "Tue 21 Oct" format.
  • Online events say "Online" in place of the venue.
  • Multi-day: "Sat 14 – Sun 15 Nov"; the badge shows the first day.
  • Cancelled rows replace time and attendance with who cancelled: "Cancelled by Esther Nakamura".
  • Type the month as "Oct"; the badge uppercases it with CSS.
