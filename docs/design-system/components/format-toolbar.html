Formatting toolbar

A small dark toolbar that appears over a text selection in a Notes block and applies inline formats. Every button has a keyboard shortcut, and the toolbar itself is reachable with Alt+F10.

WCAG 2.2 AAStatus: newft-format-toolbarAPG Toolbar

Overview

When the owner selects text in any text-bearing block except Code, the toolbar opens just above the selection with six buttons: Bold, Italic, Underline, Strikethrough, Inline code and Link. Each format button shows whether the whole selection already has that format and toggles it; Link opens the "Add a link" dialog. With the caret inside linked text, Link is replaced by Edit link and Remove link. It is part of the block editor and saves through autosave.

  • Use it only for inline formats on the selected text. Block-level changes (heading, list, quote) go through the slash menu or Turn into.
  • Never show it in the read-only view, in a Code block or while editing is paused.

Anatomy

  1. Toolbar.format-toolbar, role="toolbar" named "Formatting": inverse surface, --radius-md, --shadow-3, anchored above the selection's start.
  2. Pressed button.format-toolbar__btn[aria-pressed="true"]: accent fill with --color-fg-on-accent, meaning the whole selection is bold.
  3. Button.format-toolbar__btn: 24px minimum (32px on touch), the format's letter drawn in its own style, labelled by name.
  4. Tooltip.format-toolbar__tip: "Italic · Ctrl+I" (⌘ on macOS) under the button on hover and focus; aria-hidden, since the shortcut is in aria-keyshortcuts.
  5. Separator and Link.format-toolbar__sep sets Link apart from the toggles; Link has aria-haspopup="dialog".

Caret in a link

The caret is inside "faithtech.community". Edit link opens the dialog pre-filled ("Edit link", with Remove link in its footer); Remove link drops the href and keeps the text and its other formats.

Sizes

Not applicable. Buttons are --target-min (24px) with a pointer and --target-comfortable (32px) on touch screens; the toolbar wraps nothing and stays one row.

States

DefaultHoverFocusPressedPressed + focus
  • Pressed only when the whole selection has the format; a mixed selection shows not pressed, and pressing applies the format to all of it.
  • Hidden: no selection, a collapsed caret outside a link, a Code block, the read-only view or a paused editor.
  • There is no disabled state; buttons that can't apply are not shown.

Both themes

Responsive behaviour

  • Anchored above the start of the selection (CDK Overlay); when there is no room above (under the sticky top bar) it flips below the selection, and it shifts sideways to stay inside the viewport at 360px (L2-099 AC11).
  • On touch screens buttons are 32px, so the six buttons and the separator fit in about 220px.
  • It never covers the selected text or the caret (WCAG 2.4.11): it sits outside the selection's line box.

Theming

The toolbar uses the inverse pair (--color-bg-inverse, --color-fg-inverse) in both themes, like a toast, so it stands apart from the page. Hover tints with currentColor at 16%; pressed uses --color-accent with --color-fg-on-accent. The focus outline switches to --color-fg-inverse so it shows on the dark surface. Tooltips use the raised surface. Under forced-colors the toolbar gets a CanvasText border.

Accessibility

Role and pattern

WAI-ARIA APG Toolbar: role="toolbar" named "Formatting" (on the host element). Toggles are native buttons with aria-pressed; each names its shortcut in aria-keyshortcuts (Control+B) and in its title ("Bold (Ctrl+B)"); Cmd works in place of Ctrl on macOS. Link, Edit link and Remove link carry no aria-pressed. Focus is roving: one button has tabindex="0", the rest -1 (L2-099 AC4).

Focus

The focused button shows the 2px ring in --color-fg-inverse around it, offset from the pressed fill. Pointer clicks do not move focus out of the block (buttons prevent mousedown default), so the selection is not lost.

Labelling

Buttons are named "Bold", "Italic", "Underline", "Strikethrough", "Inline code", "Link", "Edit link" and "Remove link"; the drawn letters and icons are aria-hidden. Pressed state is announced as "Bold, toggle button, pressed".

Motion

Scales in from the bottom left over --duration-fast; reduced motion makes it appear without scaling. Tooltips fade over --duration-fast.

Touch

32px buttons on touch. The OS selection handles stay usable because the toolbar sits above the selection, not on it.

Content

  • Button names are the format's name in sentence case; tooltips read "{Name} · {Shortcut}" with "Ctrl" on Windows and Linux and "⌘" on macOS ("Strikethrough · Ctrl+Shift+S").
  • Link actions: "Link", "Edit link", "Remove link". The dialog's hint is "Starts with https:// or mailto:" and its error "Use a link that starts with https:// or mailto:".

Code

<!-- Inside ft-block-editor, positioned over the selection -->
<ft-format-toolbar
  [pressed]="pressed()"               <!-- Partial<Record<FormatMark, boolean>>: marks the whole selection has -->
  [hasSelection]="sel.end > sel.start"<!-- false: only Link / Edit link (and Remove link) are offered -->
  [inLink]="!!sel.link"               <!-- "Link" becomes "Edit link" and "Remove link" appears -->
  (format)="format($event)"           <!-- FormatMark: 'bold' | 'italic' | 'underline' | 'strike' | 'code' -->
  (link)="requestLink()" (removeLink)="removeLink()"
  (dismissed)="backToText()" />       <!-- Escape: focus back to the text -->
// focus(): Alt+F10 from the text lands on the first button

The host is role="toolbar" named "Formatting". Buttons are Bold (Ctrl+B), Italic (Ctrl+I), Underline (Ctrl+U), Strikethrough (Ctrl+Shift+S), Inline code (Ctrl+E) and Link or Edit link (Ctrl+K), plus Remove link in a link; the marks expose aria-pressed, each button has aria-keyshortcuts (Control+…) and a title such as "Bold (Ctrl+B)"; Cmd replaces Ctrl on macOS. One button is in the tab order (roving tabindex) and ← and → move between them. Mousedown is prevented so the selection stays in the text. The built toolbar has no separator or hover tip element; the mock classes below draw them for review.
